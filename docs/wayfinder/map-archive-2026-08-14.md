## Destination

A written v1 spec for verge-asm — an AGPL-3.0, self-hosted, single-tenant web application that takes seed domains and IP ranges, discovers internet-exposed assets via passive sources then active probing, and makes **exposure drift a first-class, queryable object with its own lifecycle — tracked across ports, certificates, DNS records and HTTP identity, not subdomains alone** — complete enough to hand to implementation sessions.

That emphasis is the differentiation, and it is deliberately narrow: the prior-art survey established that discovery, probing, scan-to-scan diffing and the risk signals all exist in open source today. What does not exist is change modelled as a durable object across every asset facet. The spec must earn that claim or the effort has no reason to exist.

## Notes

- **Plan, don't do.** This map produces the spec, not the implementation. Every ticket resolves a decision.
- **Recommendations are pre-accepted — run every ticket AFK.** Standing instruction from the map's dev, 2026-08-13: *"I'm taking all your recommendations on the grilling tickets. Assume I'm going with your recommendations unless I come in and say otherwise. I want to make this as AFK-able as possible."* This **overrides the ticket-type HITL rule** for this effort — `grilling` and `prototype` tickets run without waiting on a live human, which is the override the skill routes through this section. What it does **not** license is skipping the interrogation: `/grilling` and `/domain-modeling` still run in full, the session just argues both sides itself and rules, rather than leaving the question hanging. Three riders bind. **The resolution comment is where review happens, so it must be reviewable** — it names the option that lost and why it lost, because a recommendation taken silently is one the dev cannot disagree with later. **Do not manufacture consensus**: where the evidence genuinely underdetermines the answer, say so in the comment and rule anyway, flagging it as a decision taken on thin ground rather than dressing it as settled. And **stop for a scope change, never for a preference** — a resolution that would redraw the Destination, or that costs money, sends mail to a third party, or is otherwise hard to walk back, is put to the dev; everything short of that is the session's call.
- **Licence: AGPL-3.0.** The network copyleft is deliberate. Dependencies and design choices must be compatible; flag anything that would force a licence change.
- **Defensive posture.** The operator owns the assets being scanned, so no scope-consent machinery is needed — but probing safety against the operator's own production is a live concern. **Qualified by [ADR-0002](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0002-ownership-gates-probing.md):** discovery follows records outward, so "the operator owns it" is not automatically true of what discovery reaches. Ownership is derived per address and *gates* probing, which is how the premise is kept true rather than assumed.
- **Single-tenant, self-hosted** via `docker compose`. No multi-tenancy, billing, or hosted infrastructure in scope.
- **The user** is a small-org security owner. The product answers: *what of ours is exposed to the internet, and what changed?*
- **The instance is a high-value target.** Its database is a complete, current map of the operator's attack surface. Security decisions are weighed against that, not against the app's size.
- **Differentiation is narrow, and must not be overstated.** "No OSS tool does exposure drift" is **false** — see the prior-art ticket. reNgine ships working subdomain drift with scheduling and alerting. The defensible claim is narrower: drift as a *first-class, queryable object with a lifecycle*, tracked across **ports, certificates, DNS records and HTTP identity** rather than subdomains only. Any session that finds itself writing "nothing else does this" should re-read that ticket. **The margin has since narrowed**: reNgine's unreleased `release/3.0.0` rewrite already models ports, IPs, DNS and full certificate data, and still diffs subdomains only — so the gap is now *temporal modelling alone*, not data coverage. If 3.0 ships drift across the facets it already stores, this map's differentiation is gone. Re-check `api/app/services/scan.py` and `worker/app/orchestrator/finalize.py` on that branch for any diff over a model other than `Subdomain`.
- **The operator-supplied zone file is the product's spine.** A defensive tool can ask for ground truth that an offensive recon script must guess at. Every guess-based technique is gap-filling for what the zone doesn't cover. This is a structural advantage over the offensive-framed tools in the prior-art survey, and it should be visible in the domain model, the onboarding flow, and how the project describes itself.
- **A source that errors must produce no observation, never an observation of absence.** Measured: crt.sh returns spurious 404s. In a drift product, "non-200 means empty" manufactures false "asset removed" alerts.
- **Evidential coverage and operational attempt are two different records.** Established in [Scan scheduling and job execution model](https://github.com/winniel123/verge-asm/issues/9) and recorded in [ADR-0005](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0005-scan-execution-model.md) — the general form of the rule above, and the one that closes its failure path. A `Batch` records the scope it **completed**, never the scope it attempted, because the recorded scope is what licenses silence to count as evidence: a dead-lettered batch that logged "attempted 140 ports" would assert 140 absences it never measured. So every failure path writes to the *operational* record — the job, the `Dispatch` — and never inflates the evidential one. The corollary binds any session designing a surface: **the operational record is the only place several real failures are visible at all**, by construction, which is why [#22](https://github.com/winniel123/verge-asm/issues/22) exists.
- **Every seam is a place drift can be manufactured.** The generalisation of the rule above, established in [Stack and runtime for web, worker, and persistence](https://github.com/winniel123/verge-asm/issues/6): a boundary between two systems — two durability domains, two languages defining one wire format, two implementations of one measurement — is a place where a change *in the observer* can surface as a change *in the world*, and the operator cannot tell the difference. This is why the runtime lands on one of everything, why [#5](https://github.com/winniel123/verge-asm/issues/5) chose one measurement binary rather than two, and why fingerprinting is out of scope. Weigh any proposed new seam against it.
- **Three layers, and only one of them drifts.** Established in [Core domain model and ubiquitous language](https://github.com/winniel123/verge-asm/issues/7) and recorded in [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/main/CONTEXT.md): **Declared** (operator-authored input) · **Observed** (measured facts — *the only drift-bearing layer*) · **Derived** (computed conclusions — `Ownership`, `Exposure`, `Signal`). Anything Derived is a function of our own rules or thresholds, so diffing it is the seam rule above with the seam inside our own code. Before any session proposes surfacing a change, check which layer the thing lives in.
- **Cite the source that owns the claim, not the loudest authority.** Established in [Which ports are never legitimately internet-facing, and on what evidence?](https://github.com/winniel123/verge-asm/issues/21). Where a rule carries reference data, a row is admitted only on a **named claim**, **attested by the protocol's own specification, project or documented shipped default**, plus a **determinacy** check. Government and cloud-provider lists corroborate; they never carry a row alone — they are authorities on *risk*, not on *legitimacy*, they contradict each other and themselves, and taken at face value they would have put SSH and RDP on a list of ports that are never legitimately internet-facing. The generalisation is a live question ([#33](https://github.com/winniel123/verge-asm/issues/33)), but the habit binds now: any session reaching for a third-party list as evidence should ask what the *owner* of the thing says. Two practical riders — **publish the weak tier rather than smoothing it** (three rows rest on a shipped default alone and say so), and **verify quotes against the source, not a summarising layer**: [#21](https://github.com/winniel123/verge-asm/issues/21) caught four errors that had already reached its draft, including a row resting on no attestation at all and a widely-repeated `xhost(1)` warning that **does not exist upstream**. **[#46](https://github.com/winniel123/verge-asm/issues/46) makes it five and sharpens what the check has to be**: §13.5's APNIC header quote was verbatim-accurate and still wrong about what the clause permits, because it was lifted out of the page that defines its only operative term — so **verifying a quote against its source is not the same as verifying it against its context**, and a truncated quote of a conditional is the shape to watch for. **[#30](https://github.com/winniel123/verge-asm/issues/30) sharpens the habit in the direction sessions will find least convenient: a shipped default is evidence in *both* directions.** rpcbind's upstream unit file binds `0.0.0.0:111` and its maintainers answered the exposure hazard *inside the software* rather than by declaring the port off-limits — so the same route that admitted three rows attested against a fourth, and "the owner is silent" is not the same as "the owner has no position". Two riders: **a distributor is not the vendor** (Red Hat's Security Guide was declined on ownership grounds, and it contradicts itself elsewhere), and **the instrument itself is now known to be defective** — Claim 1 read literally admits WHOIS, DNS and every public web server, so it rests on an unwritten qualifier, open as [#37](https://github.com/winniel123/verge-asm/issues/37). **[#37](https://github.com/winniel123/verge-asm/issues/37) repaired the instrument and moved no row — all 38 pairs survive, tested by walking them rather than asserting it.** Five narrowings bind. **Claim 1 has a stated qualifier in two ordered steps**: the *publication test* refuses outright where the spec defines the anonymous operations as ones it performs for callers it does not identify (finger, WHOIS, DNS, HTTP — and 111/tcp, now refused on claim grounds and not only on attestation), and only then the *authority test* asks whether they write, register, execute, control a runtime, or read content carried for another party; the order is load-bearing, since the authority test alone admits every public web server. **The set is closed by construction** over the three things an internet vantage supplies — unknown principal, untrusted path, caller outside a boundary — so it reopens only if someone names a fourth property of a vantage, never on the next odd-shaped port; integrity (rides on Claim 2's successor clause), amplification (a *magnitude*, refused by §2.7) and disclosure-by-design were each tested and refused. **Claim 3's boundary is one the owner names** — same system, same cluster, or a management network — a wording fix closure forced, checked against all 16 of §4.6's exclusions and admitting none. **#30's both-directions finding is narrowed**: a shipped default attests **only where it restricts**, a restriction being a costly act the maintainer bought friction to make, while a permissive default is the absence of an act and is *silent*. The symmetric reading loses on a measurement — it deletes ~18 rows including 23/tcp Telnet and 445/tcp SMB, which carries the strongest sentence in the corpus. What #30 actually found is a **separate instrument, the remedy route**: where the owner's restricting act is aimed at the exposure hazard and **stops short of the port**, absent any prohibition from that same owner, it *excludes* — which is rpcbind, and is not memcached's UDP disablement or Docker's refuse-to-start, both of which reach the port. And **owner keys on the artefact, never the party**: a distributor owns its shipped configuration and owns nothing about the protocol, which is how Debian's `rpcbind.default` counted while Red Hat's Security Guide did not, and the self-contradiction is *evidence the line is right, never the ground for it* — a session finding a consistent distributor has read the wrong sentence. Two riders. **Closing a claim set is what surfaces rows whose class was never argued**: `161/udp`'s Claim 3 boundary limb rests on CISA, a corroborator, so §2.6's *no row rests on a government source alone* holds for 37 rows and not the 38th — disclosed as the second-weakest row rather than moved, because **a verdict changes on retrieval and none was performed**, open as [#66](https://github.com/winniel123/verge-asm/issues/66). And **amplification is the door frequency uses**: 11211/udp's *why* cell led with the magnitude §2.7 refuses for 111/tcp, corrected to its Claim 1 grounds.
- **Use the glossary's words.** [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/main/CONTEXT.md) is opinionated about vocabulary and explicit about what it refuses: **`Asset`**, **`Host`**, **`Finding`**, **`ScanRun`**, and `Discovery`/`Probe` as nouns are all rejected, each for a stated reason. A session reaching for one of them is usually about to re-introduce the failure that rejected it.
- **The design system exists and is not optional.** [`design-system/`](https://github.com/winniel123/verge-asm/tree/main/design-system) — "engineered paper": warm paper `#f7f7f4`, ink `#16160f`, one working blue `#2d4fd4`, 0px radius, hairline rules, hard offset shadows, Helvetica for UI and IBM Plex Mono for every technical value. Any session producing a visual surface — production UI, prototype, mock, slide — invokes the `verge-asm-design` skill first. Rules in [`docs/agents/design-system.md`](https://github.com/winniel123/verge-asm/blob/main/docs/agents/design-system.md). **Its visual layer is canonical; its vocabulary and IA are not** — the kit predates [#7](https://github.com/winniel123/verge-asm/issues/7) and ships a `Findings` section, a fingerprinting claim, and a Dashboard-first layout with *no drift screen at all*. - **A source ships on only if the modal operator clears its terms — and changing that later is an aperture change.** Established in [Which third-party discovery sources may ship enabled by default, given their ToS?](https://github.com/winniel123/verge-asm/issues/15) and recorded in [ADR-0003](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0003-third-party-source-consent-bar.md). Two limbs: what the *software* inherently does (query, store, retain) must be permitted, and the *modal operator* — a small commercial org inventorying its own estate — must be inside the terms. A clause barring resale of the source's data bites neither. **Ambiguous terms are asked about, not read**, and the source ships off until an answer arrives — indefinitely if none does. `Consent` is now a property of `Source` in [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/main/CONTEXT.md). The part that binds sessions beyond source selection: **enabling a source widens the aperture, and a release that flips a default widens it for every existing install at once** — so a subject first observed under a widened aperture is not "appeared". Any session proposing to change a default is proposing estate-wide drift. **The "indefinitely" branch has now been taken, four times** — [#19](https://github.com/winniel123/verge-asm/issues/19), [#23](https://github.com/winniel123/verge-asm/issues/23), [#24](https://github.com/winniel123/verge-asm/issues/24) and [#25](https://github.com/winniel123/verge-asm/issues/25) all closed as *asked, no answer* — though [#57](https://github.com/winniel123/verge-asm/issues/57) has since found the *asked* half unevidenced, and the branch is taken either way, since ambiguous terms ship off indefinitely whether the question was ignored or never put — so off-by-default is the spec's settled answer for RIPEstat, the RIPE Database and APNIC's, AFRINIC's and LACNIC's live registry paths, not a pending state. Two riders bind from here: **the ADR's "what is lost is first-run *depth*, not the capability" is false for RIPE and LACNIC**, which have no `unencumbered` fallback and so get *no* org→prefix coverage by default; and **`operator-accepted` was carrying two cases it was not designed for** — a limb-1 ambiguity (APNIC) and terms that cannot be retrieved (LACNIC) — **settled by [#34](https://github.com/winniel123/verge-asm/issues/34), which found the framing itself wrong and binds every session touching a source's terms.** The axis is not *which limb* but whether the residual unknown **varies by operator or is constant across every install**, and all four toggles gate at least one constant question — so limb 1's *"regardless of who the operator is"* governs **shipping enabled by default**, not whether the capability may exist behind an opt-in. `operator-accepted` therefore does **not** mean the operator certified they are inside the terms; it means the operator took on a reading the project declined to make, as the party actually bound by it, which is this ADR's founding move one step further out. Three riders bind. **A prompt that does not say what is unresolved collapses the value back into a self-certification**, so it states the unknowns in the project's own words in two marked groups — *what you may be able to resolve* and *what nobody has been able to resolve* — which is [#47](https://github.com/winniel123/verge-asm/issues/47). **A consent record stores the retrieved document or the retrieval failure, never a pointer** — [#15](https://github.com/winniel123/verge-asm/issues/15)'s account/timestamp/terms-URL is withdrawn, since AFRINIC's documented URL 404s and a live one can be rewritten after acceptance with nothing to compare against; note this is [#27](https://github.com/winniel123/verge-asm/issues/27)'s redistribution line staying satisfied, the copy being made by the operator's install and never shipped by us. And **`Consent` gains no fourth value** — *we could not read the terms* is a fact about our own assessment, and a property whose values all answer *whose permission does this run on* is the wrong home for it; a session reaching for a fourth case there is proposing a second property in an enum case's clothes. **[#26](https://github.com/winniel123/verge-asm/issues/26) resizes the whole registry question and every session should read this before treating a registry path as important: the modal operator is not ASN-less, they are *registry-less*.** Measured — **128,233** organisations worldwide hold any RIR delegation, against **6.4M** US employer firms and **32.3M** EU27 enterprises, so under 1% of ADR-0003's persona holds registry resources at all, and org→prefix is a **convenience** for nearly every install rather than a capability (79.1% of ASN-less holders hold exactly one IPv4 block; 97.5% of all holders hold ten or fewer). The four registry non-answers therefore cost far less than they appeared to, because **ARIN, RIPE, AFRINIC and LACNIC all key on organisation name, not ASN** — they serve the same sub-1% population. Two riders bind: **ARIN's keyless path already reaches provider-aggregatable renters** through SWIP customer objects compelled to a /29, which is the case everyone assumed was unreachable ([#38](https://github.com/winniel123/verge-asm/issues/38), [#39](https://github.com/winniel123/verge-asm/issues/39)); and the modal estate is *cloud-resident*, where all 52,680 published AWS/Azure/GCP prefixes belong to **48 registry holders and never to the operator** — so the entry point is the name-scope `Seed`, and what that does to [ADR-0002](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0002-ownership-gates-probing.md)'s probing gate is open as [#40](https://github.com/winniel123/verge-asm/issues/40). **[#38](https://github.com/winniel123/verge-asm/issues/38) re-prices the four non-answers upward and corrects #26 in the direction sessions will find least comfortable, because #26 had talked the registry question *down*.** The SWIP finding generalises at the **policy** layer — all five RIRs compel PA assignments under the End User's name, RIPE and AFRINIC with **no prefix floor at all** — but the **name search** splits 3–2, ARIN, RIPE and LACNIC reaching renters and APNIC and AFRINIC reaching them by no interface at any tier. Three riders bind. **#26 §11's pricing of the RIPE and LACNIC asks is withdrawn**: it read them as converting a sub-1% population from `operator-accepted` to `unencumbered` and concluded *"if anything the priority falls"* — false, because those terms buy the **PA-renter layer beneath** the registered population, **1,127,002** once-only customer names for RIPE alone against the **128,233** worldwide delegation holders #26 measured. It still stands for APNIC and AFRINIC, where the terms buy nothing. **The count of honest missing-capability annotations goes from one to two**, AFRINIC joining APNIC for *renters* while #26 §10.4's one-click-deep line covers AFRINIC *delegation holders* only. And **[#20](https://github.com/winniel123/verge-asm/issues/20)'s two RIPE defects are both narrower than recorded** — the 400 reproduces but has two working alternatives, and the RDAP 500 is **wildcard-specific**, controlled both ways — so any session citing them as closed doors should re-read §13.4 first. Also measured and worth not re-deriving: **`org:` was the wrong attribute to ask about**, carrying a genuine End User on 4.24% of RIPE PA where `descr:` carries one on 89.48%. **[#46](https://github.com/winniel123/verge-asm/issues/46) adds a third position to the ask-or-read fork and it is the one sessions will miss** ([ADR-0018](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0018-a-clear-conditional-is-not-an-ambiguity.md)): terms may be **clear and conditionally *permitting*** — a plain prohibition with a plain carve-out and a **published mechanism** for reaching it — which is neither the ambiguity corollary nor the plain no this ADR's second amendment assumed *clear* meant. So before reaching for the corollary, look for the mechanism and ask **whose** act it is; APNIC's was one click from a page this project had already quoted twice, and it is the operator's act, not ours. Two riders. **An unenforced gate is still a gate** — APNIC serves the bulk file anonymously, contradicting its own published process, and that is the exact mirror of *unreadable is not absent*: a source may not lose its restriction by leaving the door open any more than it may earn `unencumbered` by breaking its own link. And **`consent` keys on the instrument, never on the registry** — one registry may need two values, which the glossary already licensed (*"the same service can sit in two different states depending on how it is reached"*) — with `operator-credentialed` now covering **a grant the source actually made to that operator**, an API key or a countersigned agreement alike, against `operator-accepted`'s **reading the operator makes and bears**. Whether an operator's own act can *move* the value afterwards is [#52](https://github.com/winniel123/verge-asm/issues/52).
- **A rule may ship as a `Signal` only if its reference data changes at release cadence.** Established in [Risk signals: which ones does v1 emit from cert and protocol facts alone?](https://github.com/winniel123/verge-asm/issues/16) and recorded in [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md). The test is a question about our own intentions — *would we ever want to push updates to this list out of band?* If yes it is a signature database and it is out. Note what the test is **not**: "does the rule contain a judgement" excludes nothing (*TLS 1.0 is weak* is a judgement), and "can the operator verify it" excludes nothing either (a fingerprint cites its banner). Three consequences bind every session touching a Derived value: **signals carry no severity** — urgency belongs to the transition that surfaced them; **absent evidence yields `not-evaluable`, never "did not fire"**; and **a comparison is legal only if the effective rule version was unchanged**, where a signal reading a Derived value composes that value's version too, and versions are **per rule** so one edit never silences the set.
- **Nothing leaves because time passed, and nothing leaves by a state we invented.** Established in [Subject lifecycle: when may something leave the inventory with no enumerable source to say it is gone?](https://github.com/winniel123/verge-asm/issues/17) and recorded in [ADR-0006](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0006-subjects-leave-by-measurement.md). A subject leaves the estate only because something *measured* its absence — there is no decay, no counter, and no `stale`/`dormant`/`unconfirmed` band. The general habit for any session tempted to add a lifecycle state: **check whether the thing already has an observed value**, because a `Name` going away had one all along (`resolution` reporting a Name Error), and inventing a state means inventing a transition, which is a threshold we chose sitting inside the comparison path — the failure the three layers exist to prevent. Two riders bind beyond this ticket. **Our own resolver is `enumerable` over a scope of one name**, so enumerability never required an operator-declared scope, only a `Batch` that records what its silence covers — and any session about to declare a subject un-disconfirmable should check that first. And **the operator's "this is gone" is a `Seed` exclusion, never an `Annotation`**: opinion attached to a measured thing may not do the job measurement does. What genuinely cannot be disconfirmed — a name below a wildcard — stays, marked `Shadowed`, and that is the honest answer rather than a gap.
- **Drift is a timeline of `Span`s, and comparison is legal only within one derivation.** Established in [Drift model: how change over time is represented and surfaced](https://github.com/winniel123/verge-asm/issues/8) and recorded in [ADR-0007](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0007-drift-is-a-timeline-of-spans.md). The stored object is the **period a value was held**, keyed `(subject, facet, vantage, source)` — one timeline per source — and a `Transition` is the adjacency between two spans, derived on read and never stored. Ingest is a **fold over completed batches**, so there is no batch *pair* and no pairing step to be invalid; the batch supplies the **licence** to compare, never the pairing. **This amends [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/main/CONTEXT.md)'s three-layer table**, which every prior session read as *only Observed drifts*: every `Span` is Derived — even one folded straight from observations composes a canonicaliser version and the staleness bound — so the rule is not *never diff Derived* but **never compare across differing derivations**, enforced by a `Break` rather than by discipline. Five things bind any session from here. **Two words, not one, for what was called "not comparable"**: a `Break` has values on both sides and no licence to compare them (two causes only — a derivation version changed, or the aperture widened), a `Gap` has no value at all; `Shadowed` is a third thing again, a *value* meaning we cannot see. **History is never re-derived** — a derivation bug leaves permanently wrong history, and the fix ships as a new version and a `Break`. **No hysteresis, no confirmation counter, no suspected state anywhere in the model** — damping happens in notification only, because a flap count is a fact the operator wants and model-layer damping destroys it permanently. **Currency is `k` cadences of the Declared `Scan`** covering the thing, never a wall clock and never `Dispatch` membership. And **alert on the cause, record the consequence** — a cascade, a closing ownership gate and a widened aperture each turn one event into a burst.
- **A version moves on content, and a `Break` clamps rather than blanks.** Established in [How does a Derived value's effective version avoid moving every release?](https://github.com/winniel123/verge-asm/issues/18) and recorded in [ADR-0008](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0008-derivation-versions-move-on-content.md). **[ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md)'s "release-coupled" is a *ceiling* on how often content may change, never a claim that a version moves because a release shipped** — the alarm that opened that ticket came entirely from reading it the second way, and any session estimating breaks per year from the release cadence has made the same mistake. A version moves only on an **output-affecting change**, gated by a **golden corpus in CI** so the judgement stays human while the check is mechanical — the same structural-not-disciplinary move as [ADR-0007](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0007-drift-is-a-timeline-of-spans.md)'s `Break`, and the reason "bump only when the output changes" is not the discipline this project has refused everywhere else. The version is a **vector of named component versions**, one leaf per named `Derivation`, flattened, so a break can name the *leaf* that moved. Three things bind any session from here. **A `Break` withdraws the licence to reach back, not the data** — a view clamps its horizon to the most recent break and its **census still renders**, since a census is not a comparison — which is what makes a break cost one cadence, and in turn why breaks are uniform across a derivation rather than scoped by a predicate that would fail *silently* where a wide break fails loudly. **The cost lands on duration**: nothing crosses a break, so a truncated duration or count renders as a **labelled floor**, never a bare number — after an upgrade *exposed for 4 days* is an artefact wearing the clothes of a fact, and any session rendering a number over a window owes the operator that label. And **the product may report on itself in the coverage class**: a re-baseline message when a vector moves, fired once at the cause, whose difference set is a *description* and never a `Transition`, or the forbidden comparison walks back in through the notification layer.
- **A table deciding *where to look* is aperture; a table deciding *what an answer means* is a signature database.** Established in [What can an observation-driven insecure-listener rule establish?](https://github.com/winniel123/verge-asm/issues/31), and it is the general form of the line [#5](https://github.com/winniel123/verge-asm/issues/5) drew when it ruled out fingerprinting — which until now had only a worked example and no test. Measured in `nmap-service-probes`: **187 `Probe` directives against 12,171 `match`/`softmatch` lines**, a 65:1 split, and the ratio *is* the argument — the dispatch is small and enumerable, the interpretation is unbounded and churny. A rule stays legal if every fact it admits is read from a **spec-defined field** (an EHLO keyword, `CLIENT_SSL`, PostgreSQL's one-byte `S`/`N`, an LDAP `resultCode`, an HTTP status class), so its **verdict table has zero rows**; the dispatch table then sits in the aperture, where [ADR-0008](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0008-derivation-versions-move-on-content.md) prices growth as `revealed` rather than a version bump, and it is release-coupled *more* strictly than the sensitive list because a new protocol needs new prober code and so cannot ship out of band. Two riders. **The determinacy problem moves rather than vanishing** — the client speaks first for all but five protocols, so what a curated list suffers at the verdict, an observation-driven rule suffers at the dispatch. And **the credential line is an auth-message test**: any message the protocol defines except one entering the authentication exchange, where *an empty credential is still a credential* — which admits Redis `PING` and an unauthenticated `GET /`, and excludes FTP `USER anonymous`, an anonymous LDAP simple bind, MQTT `CONNECT` and PostgreSQL's `StartupMessage`.
- **Redistribution is a separate permission from use, and the party who needs it is the project.** Established in [Bundle the CAIDA and delegated-stats tables in the image, or fetch them live?](https://github.com/winniel123/verge-asm/issues/27). [ADR-0003](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0003-third-party-source-consent-bar.md)'s two limbs both ask what the **operator** may do at runtime, and the ADR says in terms that a clause barring redistribution *"does not fail, because the operator is not redistributing"* — true, and irrelevant the moment **we** are. Anything the project **ships** — reference data in the image, a bundled corpus, a vendored dataset — is a build-time act by us, and the bar has no limb for it. Deliberately recorded as a separate rule rather than a third limb, because it binds on data we never query at runtime. Measured instance: CAIDA's Public-AUA grants *"a limited, non-exclusive, **non-transferable**, non-assignable, and terminable license to **copy, modify, and use**"* and adds *"No license is granted for any other purpose and there are no implied licenses"* — so bundling was never a cost to weigh against image size, it was an act with no licence behind it. The rider that generalises: **`unencumbered` is a verdict about querying, not about shipping**, so a source cleared by ADR-0003 may still not be redistributable, and any session reaching for "bundle it so first run needs no network" owes that second check. Note also what the ADR-0003 *ask-don't-read* habit does **not** cover here — clear text is not ambiguity, so no email was sent; asking would have been a request for an exception rather than a clarification, and unlike [#19](https://github.com/winniel123/verge-asm/issues/19)/[#23](https://github.com/winniel123/verge-asm/issues/23)/[#24](https://github.com/winniel123/verge-asm/issues/24)/[#25](https://github.com/winniel123/verge-asm/issues/25) the fallback loses nothing. **[#46](https://github.com/winniel123/verge-asm/issues/46) is the second instance of that habit and the first where the fallback loses something real** — APNIC's bulk file is the only instrument reaching the 657,044 named PA assignments [#38](https://github.com/winniel123/verge-asm/issues/38) measured — and it still did not license an ask, because the clear text names a route the **operator** walks and we cannot. It also fixes this rule's reach: it binds on what **we** ship, so a **local copy fetched by the operator's own install is not redistribution**, which [#34](https://github.com/winniel123/verge-asm/issues/34) had already settled in passing for the consent record and which now disposes of the whole indexed-dump class. The residue is a cost ruling, not a licence one: **no third-party bulk registry dump enters v1**.
- **The probing gate reads Declared input only, and no third party's file can open it.** [ADR-0002](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0002-ownership-gates-probing.md) **amended** by [#27](https://github.com/winniel123/verge-asm/issues/27): its original *"address-scope seeds **plus RDAP expansion of their organisation's ranges**"* is withdrawn, and `Ownership` is computed from `Seed`s alone. Registry lookups of every kind now **propose** address scopes that the operator confirms into `Seed`s, and an unconfirmed proposal is read by nothing. The forcing measurement is worth carrying because it recurs: one address-scope seed inside AWS shares its delegated-stats opaque-id with **177 resources totalling 76,046,336 IPv4 addresses**, against a median ARIN holder of **512** — so under the original wording the modal, cloud-resident install ([#26](https://github.com/winniel123/verge-asm/issues/26)) opened the gate on 76 million of Amazon's addresses. Three things bind from here. **A size cap and an exclusion list were both refused** — the first is an invented threshold inside the safety path, the second is [#31](https://github.com/winniel123/verge-asm/issues/31)'s signature-database line — so the remedy is confirmation, which was already this ADR's escape hatch used in the correcting direction. **Confirming a proposed *scope* once is not ADR-0002's rejected "confirm each discovered address"**, which stays rejected: one is a boundary declaration the operator already authors, the other is a per-subject approval queue inside the discovery loop. And **registry accuracy stops being a safety property** — a wrong expansion now yields a wrong proposal the operator declines, which is what makes the delegated files' own *allocated-not-current* caveat survivable rather than load-bearing.
- **Completeness of the numerator is measurable; completeness of the estate is not — so it never gets a number.** Established in [Prototype the Coverage screen and the board's coverage statement](https://github.com/winniel123/verge-asm/issues/28). [#22](https://github.com/winniel123/verge-asm/issues/22)'s two axes were cut on the **verb** — a fault is ours, an invitation is yours — and rendering them showed the cut does not hold, because `crt.sh` is a source that is *faulty*. The cut that holds is **role**: a source that **fills a declared scope** moves the coverage figure and its failure is a fault; a source that **proposes new scopes** cannot move it at all, because coverage is measured against what the operator declared. Enabling the RIPE Database cannot raise 99.3%, only reveal that 99.3% was of the wrong estate — so **the propose half carries no percentage, no bar, and no `unknown` in a cost column, ever.** This is the direct consequence of `Seed` being a *scope declaration* ([#7](https://github.com/winniel123/verge-asm/issues/7)), and any session tempted to score estate completeness is proposing to measure the thing the operator is the only source for. Two riders bind. **Anything derived that shows a figure over a window owes three densities, not one** — the board's coverage statement is a hairline strip, an ink bar reading *this is a sample*, and the full precondition panel, because a fixed treatment is dishonest at the bottom of its range; the threshold between the first two is **#22's operator-configurable alert threshold reused**, never a second constant, and note that #22's justification for making it configurable (*"changes only who gets woken"*) is now literally false and survives only in its real form — it sits outside the comparison path. And **a census survives a `Break` but not its derivation's precondition failing**, recorded in [ADR-0008](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0008-derivation-versions-move-on-content.md): a break costs the comparison, a precondition failure costs the value, and "0 exposed" with no internet vantage would be the no-false-absence failure arriving through the census instead of through a `Batch`.
- **A list that must contain another list is not two lists, it is a union.** Established in [Hot-set transport defects and the sensitive-subset-of-hot invariant](https://github.com/winniel123/verge-asm/issues/29) and recorded in [ADR-0009](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0009-verge-core-is-a-union.md). `verge-core` is now **derived** — `frequency-set ∪ sensitive-list` — so [#21](https://github.com/winniel123/verge-asm/issues/21) §6's build-time invariant `sensitive ⊆ hot` becomes a **definition that cannot fail** rather than a test that can be forgotten: [ADR-0007](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0007-drift-is-a-timeline-of-spans.md)'s `Break` and [ADR-0008](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0008-derivation-versions-move-on-content.md)'s golden corpus one level down, and it does **not** re-open the laundering §6 closed, because normativity forcing probe-scope is what *cost yields to correctness* already licensed. The forcing measurement is that **none of the four missing pairs belongs in the hot set on the hot set's own evidence standard** — 512/tcp ranks 239th by open-frequency, 4369, 25672 and 27019 rank nowhere — so `verge-core` had not been a frequency-derived set since [#21](https://github.com/winniel123/verge-asm/issues/21) landed; the union was implicit and hand-maintained, which is exactly how they went missing. Four things bind sessions from here. **Both lists key on `(port, transport)`, and the re-key reaches the `Batch` scope record** — not for the invariant but because a batch recording `{161}` asserts an absence over a transport it never touched, which is [ADR-0005](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0005-scan-execution-model.md)'s dead-lettered-batch failure arriving through the *key*; note [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/main/CONTEXT.md) was already right, `Service` having been the `(Address, port, transport)` triple since [#7](https://github.com/winniel123/verge-asm/issues/7), so the lists were disagreeing with the model they feed. **The pre-release exemption is refused as *vacuous*, never *waived*** — `revealed` is a property of a timeline that already exists and before the first install there are none, so no freeze date is needed and none can be quietly extended; any session reaching for *"we haven't shipped yet"* is proposing a policy with exactly one user in order to avoid a mechanism ADR-0007 already prices at zero, port tiers being one of its three named aperture inputs. **"Correcting a mis-aimed port" is not a kind of change** — it decomposes without residue into a removal (the old timeline stops being fed and opens a `Gap`: *we stopped looking*, withdrawing nothing) and an addition (`revealed`) — and a change-kind defined by *our intent* rather than by subjects is the door ADR-0007 closed when it made `Break` structural. And **a port the operator can hide is a signal the operator can silence**, so `verge-core` is computed and the operator edits the frequency half alone; the lost *"don't probe 4369"* is [#22](https://github.com/winniel123/verge-asm/issues/22)'s refused suppression arriving through the port list, precedented by [ADR-0006](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0006-subjects-leave-by-measurement.md) putting estate removal on `Seed` rather than `Annotation`.
- **A rule reads a leg, never a state — a state enum is a projection, not the thing.** Established in [Does sensitive-port-exposed fire on edge-only as well as exposed?](https://github.com/winniel123/verge-asm/issues/32) and recorded in [ADR-0010](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0010-exposure-composes-two-reaches.md). Read [#14](https://github.com/winniel123/verge-asm/issues/14)'s table literally and its five `Exposure` states are **not a partition** — `exposed` is defined as *"reachable from an internet vantage"* and `edge-only` as *"reachable from the internet but not internally"*, so the second is a **subset** of the first, and any rule testing `state == exposed` silently never fires on the more alarming case. `Exposure` is therefore now **composed** from two `Reach`es, one per **`Vantage class`** (`internet` / `internal`), and the five states are what that grid *projects to*. Four things bind sessions from here. **`Reach` has two values and no third** — `reached` / `not-reached`, with *we did not look* being a `Gap`, because a `Batch` whose recorded scope excludes the port never feeds the timeline; a session reaching for `not-checked` is re-inventing `Gap`, which is [ADR-0006](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0006-subjects-leave-by-measurement.md)'s warning verbatim. **#14's most careful distinction turns out to have been a hole all along** — `firewalled` vs `internal-only` is *value* vs an absent leg on the internet side, one state and a hole named twice, two tickets before `Gap` existed (and [#45](https://github.com/winniel123/verge-asm/issues/45) corrects *`Gap`* to **no timeline** here, and withdraws the second name) — which is worth knowing because the same retrofit may be available elsewhere the model drew a pair by hand. **The flagship is a column move, not a cell move**: what the product exists to catch is the internet `Reach` going `not-reached` → `reached`, spanning `firewalled` → `exposed` **and** `firewalled` → `edge-only`, so a board promoting one hero cell buries half its own headline ([#45](https://github.com/winniel123/verge-asm/issues/45)). And **`sensitive-port-exposed` is renamed `sensitive-port-reached-from-internet`** — a signal named for a state it does not read is the `Host` defect, and the new name encodes its predicate; the old name stands unrewritten in [#16](https://github.com/winniel123/verge-asm/issues/16), [#21](https://github.com/winniel123/verge-asm/issues/21), [#29](https://github.com/winniel123/verge-asm/issues/29) and [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md). Two riders. It is the **only v1 signal that reads `Exposure`** — every other rule fires on an `Endpoint` whose evidence already presupposes a reach, and gating them would smuggle severity back in as evaluability. And **[#28](https://github.com/winniel123/verge-asm/issues/28)'s rider is narrowed**: *"a subject whose vantage is unavailable holds no `Exposure` at all"* is true of a leg that went silent and false of one never configured, where #14 deliberately built the no-prober install to be a complete internal inventory — both survive because a silent timeline yields no span and therefore **no transition to `internal-only` to render**, which is what stops a dying prober from de-escalating every `exposed` service in the estate overnight.
- **A signal reads a value, and where the value is absent the answer is already `not-evaluable` — so *may a signal fire on absence?* is never the question.** Established in [Does dangling-delegation join the v1 signal set, on evidence that is a failure?](https://github.com/winniel123/verge-asm/issues/35) and recorded as amendments to [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md) and [ADR-0006](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0006-subjects-leave-by-measurement.md). The ticket's hardest-looking question was a **forced choice with no middle**: either the failure is an observed *value*, in which case the rule is ordinary, or it is absent evidence, in which case [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md) answered it two tickets ago. That **voids** the operational-record worry rather than resolving it — nothing reads a `Dispatch` and the comparison path never softens — and any session that finds itself asking whether some barrier is softer than it reads should first check whether the thing it wants to read is a value. Four things bind from here. **ADR-0004's cadence test is the *gate*; [#16](https://github.com/winniel123/verge-asm/issues/16)'s v1 list is that test's output, not a second bar** — *"the set is closed"* was a fact about one session, and reading it as a rule had already cost [#8](https://github.com/winniel123/verge-asm/issues/8) and [#17](https://github.com/winniel123/verge-asm/issues/17) real work, so a candidate is admitted on the cadence test alone and *it adds a measurement* is a **scope** cost to weigh, never a correctness objection; a bar erected to protect the **list** rather than the **property** would have excluded this ticket for the wrong reason. **Attribution is bought structurally or not at all** — a stub resolver's SERVFAIL cannot separate the operator's dead delegation from our own bad upstream, so the binary queries the delegated authorities **directly**, which is [#14](https://github.com/winniel123/verge-asm/issues/14)'s move turning a *declared* vantage into a *verified* one; the alternative, repetition plus multi-vantage agreement, is the *whose fault was it* inference that turns a signal into a coverage gap wearing a value's clothes. **The word belongs to the protocol**: RFC 8499 §7 defines *lame delegation*, so `Lame` enters as a fifth `resolution` outcome under the RFC's own name rather than a security taxonomy's, and both signals are named for the predicate they read — `lame-delegation` and `cname-target-name-error` — because [ADR-0010](https://github.com/winniel123/verge-asm/issues/32) established that a signal named for a conclusion its evidence cannot carry is the `Host` defect. And **a clear is not always good news**: these are the first signals alerting in *both* directions, since `cname-target-name-error` stops firing when the target starts existing — the operator re-provisioned, **or somebody else claimed the orphaned name** — so a clear reads *this changed, look at it* and never *resolved*, and any session wording a notification should check the clearing edge before assuming it is reassurance. Two riders. **Neither rule contains a number**, because persistence is the span's duration once the failure is a value — an `N` in a predicate would destroy the flap count [ADR-0007](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0007-drift-is-a-timeline-of-spans.md) deliberately preserved *and* cost a `Break` per adjustment, which is why [#4](https://github.com/winniel123/verge-asm/issues/4) §7.3's *"require two consecutive runs"* is overruled rather than inherited: it was damping bought to compensate for attribution the delegation walk now buys directly. And **the un-disconfirmable residue has a second member** — names beneath a lame delegation can never receive a Name Error, so they hold a `Gap`, neither `Shadowed` (that is a *value*) nor inherited `Lame` (that asserts about the child what was measured about the parent) — and unlike a wildcard it is a defect the operator can **fix**, an escape route [ADR-0006](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0006-subjects-leave-by-measurement.md) could not previously offer.
- **A facet is six parts, and every canonical value is a closed union.** Established in [Canonical form per facet: when are two observations of one facet equal?](https://github.com/winniel123/verge-asm/issues/36) and recorded in [ADR-0011](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0011-a-facet-is-six-parts.md). [#7](https://github.com/winniel123/verge-asm/issues/7)'s *adding a facet means writing a canonicaliser* **does not survive** six real ones: a facet needs a value space, a **decoder per source**, a canonicaliser, a **differ**, a **discriminator**, and a **batch-scope obligation**. What #7 was protecting is untouched and is the part that mattered — adding a facet still never means writing a drift implementation, the fold and `Span`/`Break`/`Gap`/`Transition` being facet-agnostic — so any session adding a seventh facet should check it wrote all six, the specific failure being to write the canonicaliser and skip the batch-scope obligation. Five things bind from here. **Source shape is a separate versioned derivation from canonical form**: a **decoder** per `(facet, source)` and a **canonicaliser** per facet, because one canonicaliser swallowing every shape means a `crt.sh` parser fix `Break`s the timelines our own handshake produced, while one per pair puts two sources' values in different spaces and leaves [ADR-0007](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0007-drift-is-a-timeline-of-spans.md)'s *report the conflict* nothing to compare — and **a decoder that helpfully normalises is an unversioned canonicaliser wearing a parser's clothes**. **Every value space is a closed union, never a record with optional fields**, because each facet's measured negatives — `NoTLS`, `NotHTTP`, a Name Error, `refused` — are values, and collapsing them into absent fields sends [#16](https://github.com/winniel123/verge-asm/issues/16)'s *plaintext HTTP with no HTTPS* to `not-evaluable` on exactly the estates where it is true; `Gap` stays reserved for *we did not look*. **A value needing two measurements is decided by the measurement binary inside one batch, never assembled afterwards** — `Shadowed`, `Lame`, `NoTLS`, `NotHTTP` — since assembling `Shadowed` from a second observation puts a cross-observation dependency, with its own currency problem, inside the comparison path; the price is that the prober is now load-bearing for what a value *is*, which is [#49](https://github.com/winniel123/verge-asm/issues/49). **Creating values where none existed costs `revealed` or nothing; reinterpreting an input that already had a value costs a `Break`** — so a *strictly additive* union variant (every corpus row whose output moved previously produced **no observation**, checked in CI) ships with no break and one re-baseline message, which is what stops `Lame` blinding every `resolution` timeline in the estate for a cadence. And **the `{161}` defect was in the timeline key**: `dns-record` needs a **facet-defined discriminator** or a batch that queried MX and not TXT asserts an empty TXT RRset, and the tell that this is the general shape is that `reachability` never needed one *only because `Service` already carries port and transport*. Two riders. **[#16](https://github.com/winniel123/verge-asm/issues/16)'s `tls-1.0/1.1 negotiated` was reading our own ClientHello** — a library upgrade moves it estate-wide with nothing in the world having changed, and it answers the wrong question — so it becomes **`tls-1.0-accepted`** on a sixth facet, `tls-acceptance`, whose **candidate set is the `Batch`'s recorded scope and never part of the value**; aperture now has **five** inputs, the qtype set and the TLS candidate set joining sources, port tiers and the ownership gate. And **the body hash is refused**: its normalisation function is an unbounded corpus of strippers, ADR-0004's out-of-band tell, so `http-identity` admits only **named spec-defined fields from a closed, release-coupled set of field names** — which is [#31](https://github.com/winniel123/verge-asm/issues/31)'s zero-row verdict table with the header-name list closed too, and the same constraint is what makes the **differ unversioned**: a pure function of two canonical values that may consult nothing else, anything richer being a `Signal`.
- **A thing that produces no observations is not a `Source` — it yields `Proposal`s, and only `consent` applies to it.** Established in [Is the ARIN SWIP customer path a Source in its own right, and may it gate probing?](https://github.com/winniel123/verge-asm/issues/39) and recorded in [ADR-0012](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0012-a-proposer-is-not-a-source.md). The ticket asked what the SWIP path's `authority` must be, and the answer is that **the question was malformed rather than hard**: `authority` governs *whose word puts a subject in the estate*, `completeness` governs whether *silence* is evidence, and after [#27](https://github.com/winniel123/verge-asm/issues/27) a registry lookup does neither — it hands the operator a candidate scope. **[#28](https://github.com/winniel123/verge-asm/issues/28) had already made the identical cut from the coverage side** (*the propose half carries no percentage, no bar, ever*), so two decisions had each severed half of one distinction and the propose half was still wearing the word `Source` — the `Host` defect, one term reading as two things. `consent` survives untouched because it governs whether we may make the **request**, which happens whether or not anything observable comes back, so [ADR-0003](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0003-third-party-source-consent-bar.md) still governs proposers in full and **nothing here widens an aperture**. Four things bind from here. **The safety framing of registry accuracy is dead and sessions keep resurrecting it** — this ticket was filed hours after #27 on a premise #27 had just withdrawn, so any session reading [ADR-0002](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0002-ownership-gates-probing.md)'s *"plus RDAP expansion"* sentence on `main` is reading withdrawn text; a wrong registry record now yields a **proposal the operator declines** and costs coverage, never safety. **`Proposal` is Declared and has no timeline**, which dissolves rather than answers the ticket's remaining questions — a stale record is not a value-or-`Gap` question, and `Citation` is untouched because a proposal introduces no subject and chains still terminate at the confirmed `Seed`, with the proposal retained as provenance one hop above where `Citation` goes. **Declining is a `Seed` exclusion, not a suppression** ([ADR-0006](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0006-subjects-leave-by-measurement.md): *this is not mine* is a boundary claim), which **extends `Seed` exclusions from names and subtrees to address scopes** — handed to [#40](https://github.com/winniel123/verge-asm/issues/40) as a settled input. And **the SWIP path ships because declining it would cost more than shipping it**: [#15](https://github.com/winniel123/verge-asm/issues/15) already ships `entities?fn=` keyless and the `C…` customer objects come back in that same response — 227 of 257 measured — so this is **not an addition, it is ceasing to discard**; the residual cost is one fetch per handle against a registry with no published rate limit, a constraint for [#12](https://github.com/winniel123/verge-asm/issues/12) and not a consent question. The habit that generalises past this ticket: **a decision that changes what may be *read* should grep the glossary for the clauses it invalidates.** #27 left two standing for a day — `Vantage class` re-verifying a prober's side of the boundary against *"registry ranges the system already holds"* next to a safety check, and `Ownership` still *"computed against seeds and registry data"*. Both now read `Seed`s alone, and the cost of the first is stated rather than buried: a vantage inside **undeclared** operator space verifies as `internet` and **over-reports `exposed`**, which is the loud failure and the intended one, landing on [#22](https://github.com/winniel123/verge-asm/issues/22)'s `Coverage` where #27 already routed this same cost.

The residue — a rule **opening at `fired`** with no message above it, a dangling CNAME on an existing `Name` — is refused for v1 as #65, not blocking #12

Whoever discharges this patch should verify it under [#21](https://github.com/winniel123/verge-asm/issues/21)'s standard or move the number
- **Whether RouteViews joins the default set, and what it displaces.** [#20](https://github.com/winniel123/verge-asm/issues/20) found it replaces RIPEstat's `announced-prefixes` outright under **CC BY 4.0**, and that it is the only source measured in this project whose rate limit a naive client cannot turn into an error — it paces to ~1 req/s rather than 429ing, which under the no-false-absence rule is a materially different safety property from every other source. What stays fog is whether the BGP leg is worth having at all: [#20](https://github.com/winniel123/verge-asm/issues/20) measured **0 of 100** announced Safaricom prefixes falling outside a registered block, and 2 of 11 for a small UK host, so the folklore case for BGP catching untidily-registered space is much weaker than assumed. Not sharp yet because it likely depends on [#26](https://github.com/winniel123/verge-asm/issues/26) — an ASN-less operator gets nothing from a route collector either
- Importing existing inventory (CSV, DNS zone data)
- Whether the audit trail is surfaced in the UI — named accounts create the data; presenting it is a separate question. **Adjacent to [#22](https://github.com/winniel123/verge-asm/issues/22)'s `Coverage`** but deliberately not folded into it: an audit trail records what *operators* did, the operational record what the *system* did, and conflating them would put "admin enabled RIPEstat" and "prober unreachable" in one list. Worth deciding whether they share a home even so, since both are answers to "why does the data look like this?" **Weakened as a requirement by [#8](https://github.com/winniel123/verge-asm/issues/8)**, which removed the strongest reason to need it: aperture changes are detected from the `Batch`'s own recorded source set, so *why did 200 addresses appear last night* is answerable from the drift model alone and needs no audit trail — and it works identically whether a release or an admin caused it, which an audit trail could never have covered. What is left is the ordinary accountability case, which is a weaker argument than the one it replaces

- **Whether [#21](https://github.com/winniel123/verge-asm/issues/21)'s claim/attestation/determinacy standard and [#31](https://github.com/winniel123/verge-asm/issues/31)'s spec-defined-field test are two instruments or one.** [#31](https://github.com/winniel123/verge-asm/issues/31) excluded MongoDB on [#21](https://github.com/winniel123/verge-asm/issues/21)'s grounds while admitting everything else on its own test, which suggests they are **complementary** — one governs what a *curated list* may assert, the other what a *measurement* may conclude — rather than rival answers to one question. If that is right it should be stated, because [#33](https://github.com/winniel123/verge-asm/issues/33) is about to ask whether the first generalises and the honest answer may be *"to curation, yes; to observation, a different instrument already applies"*. Adjacent to [#37](https://github.com/winniel123/verge-asm/issues/37), which is repairing the first instrument, and deliberately not folded into it: repairing an instrument and deciding its reach are different acts. **#37 has now closed**, so the first instrument is repaired and this patch is purely about reach — and #37 found a **third** relationship worth carrying into [#33](https://github.com/winniel123/verge-asm/issues/33): [ADR-0030](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0030-an-offer-is-admitted-on-a-finding-or-on-a-falsity-it-prevents.md) already ruled an **offer** a third instrument, admitted on a finding or a falsity and **never on an attestation**, so the honest shape may be three instruments rather than two

- **Whether a name resolving to a private-range address from an internet vantage joins the signal set.** Surfaced as by-catch by [#48](https://github.com/winniel123/verge-asm/issues/48) and deliberately not ruled on there, since it is not a cross-source disagreement and was outside that ticket's question. Publishing an RFC 1918 / RFC 6598 / RFC 4193 address in public DNS is a real internal-topology disclosure that nothing in the v1 set catches — [ADR-0010](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0010-exposure-composes-two-reaches.md)'s `Exposure` does not, because the internet prober simply cannot reach the address and the service reads `firewalled`. The rule would read `resolution`'s existing address set from an internet-class vantage against the IANA Special-Purpose Address Registry, which is closed and spec-defined, so it clears [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md) on its face and needs no new field — meaning [ADR-0015](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0015-the-value-space-is-the-commitment.md) gives it no deadline and it is a pure scope call. Sharp enough to ticket whenever it is worth the slot

- **Whether `dns-record` keys on `Address` as well as `Name`.** Surfaced by [#62](https://github.com/winniel123/verge-asm/issues/62) while ruling PTR out of the v1 qtype set, and deliberately not settled there. PTR is a `dns-record` qtype whose subject is an `Address`, not a `Name`, so admitting it means the facet holds **two subject kinds** — a discriminator-and-key question of the same shape as [ADR-0011](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0011-a-facet-is-six-parts.md)'s qtype discriminator, one level up. Not sharp because the answer probably depends on whether reverse-walking an owned range earns its place at all, and [#26](https://github.com/winniel123/verge-asm/issues/26) measured that population at under 1%. Note it is also the repair path for [#55](https://github.com/winniel123/verge-asm/issues/55)'s one open item, since a PTR is a *measurement* rather than a list and would let the custody-extension message say what an entering address is without naming a provider

## Out of scope

- **Full vulnerability scanning** (nuclei templates, CVE detection) — v1 reports only risk signals that fall out of probing for free
- **Operator-authored signal rules** — ruled out for v1 in [Risk signals: which ones does v1 emit from cert and protocol facts alone?](https://github.com/winniel123/verge-asm/issues/16). A user-written rule is an un-versioned, un-reviewed derivation inside the comparison path that per-rule versioning and the alerting gate exist to make trustworthy — and the first thing anyone would write is the signature matching [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md) deliberately excluded, re-entering through a door we opened ourselves. Plausible for v1.1 once `Annotation` and the versioning story have run in production. The tension is worth keeping visible: the release-coupling test is defensible for **what we ship**, and becomes paternalistic if it is still refusing the operator's own corpus in v2
- **Technology fingerprinting** (Wappalyzer-style signature detection) — ruled out in [Build, vendor, or shell out for discovery and probing?](https://github.com/winniel123/verge-asm/issues/5) on drift-integrity grounds, not cost: a fingerprint verdict is a function of the signature database, so diffing it reports a change in the observer as a change in the world, across the whole estate at once. The general rule it generalises to — *only observed values enter drift* — binds beyond this one feature
- **A JSON API and API tokens for programmatic access** — ruled out for v1 in [Stack and runtime for web, worker, and persistence](https://github.com/winniel123/verge-asm/issues/6). With a server-rendered htmx UI no API falls out for free, so shipping one is a deliberate act — and an API token is a bearer credential that **bypasses the TOTP** decided in [#11](https://github.com/winniel123/verge-asm/issues/11), guarding a database that is the operator's complete attack surface. The integration need is **push, not pull**: nobody polls an ASM tool, they want to be told when the internet `Reach` leg goes `not-reached` → `reached` ([ADR-0029](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0029-an-alert-fires-on-a-leg.md); this entry originally said `firewalled` → `exposed`, a cell pair, before [#45](https://github.com/winniel123/verge-asm/issues/45) made it a block and [#58](https://github.com/winniel123/verge-asm/issues/58) made it a leg), which the in-scope notification-channels question already carries. A session-authed CSV/JSON export covers getting the data out with no new credential class
- **Cloud provider connectors** (AWS/Azure/GCP CAASM) — deferred past v1
- **Hosted multi-tenant SaaS** — self-hosted only
- **Offensive / bug-bounty workflows** against assets the operator does not own
- **SSO / OIDC / reverse-proxy forward-auth** — decided against for v1 in [Auth and access model for a self-hosted deployment](https://github.com/winniel123/verge-asm/issues/11); header-trust auth is a bypass class of bug when the proxy is misconfigured, and OIDC is real implementation work the v1 destination doesn't require
- **A `partially-lame-delegation` signal** — ruled out for v1 in [Does dangling-delegation join the v1 signal set, on evidence that is a failure?](https://github.com/winniel123/verge-asm/issues/35). A delegation where some but not all nameservers are lame is a real resilience defect and a real precursor to the total case, but the name still resolves, so `resolution` has not moved and nothing about the estate's exposure changed. The per-nameserver detail is still **recorded** on `dns-record`, so this is deferred rather than discarded and v1.1 can add the rule with no rework
- **A rule comparing the zone file's records against what the authority serves** — deferred in [Does zone-declared-name-does-not-resolve join the signal set, and what else does per-source keying expose?](https://github.com/winniel123/verge-asm/issues/48). *Your file says this MX and your zone serves that one* is a real config-drift finding and it is refused for v1 on [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md)'s own test arriving one level down: a zone export expresses things the wire does not — provider `ALIAS`/`ANAME` pseudo-records, apex CNAME flattening, `$GENERATE`, `$INCLUDE`, provider-side DNSSEC signing, SOA serials, apex NS sets the provider rewrites — so the decoder needs a stripper per convention forever, and a signal's effective version composes its decoder's. [ADR-0013](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0013-custody-is-control-and-extends-by-declaration.md) already refused to rest a safety property on this same ground, Route 53's API distinguishing `ALIAS` from `A` where **Cloudflare's is unmeasured**, failing *silently*. Deferred rather than discarded: it becomes legal the moment somebody measures what the major providers' exports actually emit, and that same measurement is what would price the noise floor of `resolved-name-absent-from-zone`. The v1 rules stay on the readable side of one line — **a rule may read which names a zone contains, never what records it holds for them.**
- **The wire-protocol prober and the `listener-negotiation` facet** — ruled out for v1 in [Does the observation-driven listener rule ship in v1, and at what granularity?](https://github.com/winniel123/verge-asm/issues/41). A new facet, a versioned canonicaliser with a golden corpus, plus prober `Derivation` leaves of its own, per-protocol encoders and parsers, a ~14-row dispatch table and an expanded safety surface against production — buying **six ports** and **zero** net new firings across all 38 rows of the sensitive list. It is genuinely deferrable rather than merely deferred: the facet is wholly new, so every timeline it opens is an *opening*, and [ADR-0011](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0011-a-facet-is-six-parts.md) prices the whole addition at `revealed` plus one message with no `Break`. The cost is stated rather than hidden — v1 loses the AMQP `ANONYMOUS` measurement (the clearest case in the survey of reaching where the curated list cannot), IMAP's `LOGINDISABLED` conditional MUST (the best-founded row in the note), and RDP's *is CredSSP required* on a port [#21](https://github.com/winniel123/verge-asm/issues/21) had to exclude. §5's per-protocol costing in [`docs/research/insecure-listener-rules.md`](https://github.com/winniel123/verge-asm/blob/main/docs/research/insecure-listener-rules.md) is preserved so a later effort can take protocols one at a time; the first thing it must close is the question §7.2 skipped — it argues a wrong dispatch guess fails safe for the *data* and never asks whether it is safe for the *listener*. **[#49](https://github.com/winniel123/verge-asm/issues/49) corrects this entry's pricing of the corpus and makes the deferral cheaper than it reads.** "A golden corpus of a new kind (captured wire transcripts)" is wrong on the medium: corpus rows are **authored peer scripts with a claim in prose**, run hermetically in-process, and captured transcripts are refused outright because a capture carries no claim for a human to review. So the new-kind cost is not a capture rig — which is what made it look expensive, and which #31 could not have built anyway with Docker Desktop refusing to start — it is one prober leaf per protocol the effort takes on, priced at `revealed` plus one message under [ADR-0011](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0011-a-facet-is-six-parts.md)'s strictly-additive rule exactly as the facet is. The rider that survives and gets sharper: because every wire-format claim in §5 is **spec-verified rather than measured**, each authored row encoding one of them must say so on the row
- **Third-party bulk registry dumps as an instrument** (APNIC's `apnic.db.inetnum.gz`, and the RIPE and AFRINIC dumps with it) — ruled out for v1 in [May verge-asm index APNIC's bulk file, given its header bars storage in a retrieval system?](https://github.com/winniel123/verge-asm/issues/46). **Not on the licence**: [ADR-0018](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0018-a-clear-conditional-is-not-an-ambiguity.md) found APNIC's header clear and conditionally permitting, and the tier `operator-credentialed`. It is out because **the credential is not machine-checkable and the download is not gated** — `ftp.apnic.net` serves the file to anyone — so the toggle would assert a signed agreement the software can never see, which is [ADR-0003](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0003-third-party-source-consent-bar.md)'s rejected **declared-status bar** rebuilt with the project holding the pen. Genuinely deferrable rather than merely deferred: [#43](https://github.com/winniel123/verge-asm/issues/43) prices adding or dropping a proposer at **no drift consequence whatever** — no `revealed`, no `Break`, no version bump — so v1.1 may take it up with no rework. Ruling out the class also disposes of the RIPE and AFRINIC dump terms `docs/research/asn-less-operators.md` §13.9 recorded as unassessed, without assessing them. The cost is stated rather than hidden: APNIC's 657,044 named PA assignments ([#38](https://github.com/winniel123/verge-asm/issues/38)) stay unreachable by name at any setting, which is one of the two honest missing-capability annotations and is now **final rather than pending a licence question**. Does not touch RIPE's `fulltextsearch` or any live registry path
- **The CAA and PTR qtypes** — deferred in [What does the measurement binary actually offer, now that a default may not stand in for a declaration?](https://github.com/winniel123/verge-asm/issues/62). CAA's only recorded rationale in this repo is [#3](https://github.com/winniel123/verge-asm/issues/3) §3.1's *"a mismatch between CAA and observed CT issuance is a drift signal"*, and [#56](https://github.com/winniel123/verge-asm/issues/56) ruled CT mis-issuance and any CT-fed facet out of scope — **the rationale was withdrawn three tickets ago and the row survived it**, which is [#47](https://github.com/winniel123/verge-asm/issues/47)'s hazard inside a research document. On its own *the CAA record changed* proves too much: it is true of every qtype. PTR serves the sub-1% population [#26](https://github.com/winniel123/verge-asm/issues/26) measured and additionally needs `dns-record` to key on `Address`, which is fog. Genuinely deferrable with no rework: a qtype is a discriminator in the **key**, so adding one **opens** a timeline and costs `revealed` plus one message with no `Break`
- **DNSSEC records in `dns-record`, and the DO bit** — ruled out in [#62](https://github.com/winniel123/verge-asm/issues/62). Setting DNSSEC OK enlarges every answer with RRSIGs and so multiplies the TCP-fallback rate, to collect records no declared qtype holds and no v1 rule reads. The cost is stated rather than hidden: **v1 records nothing about DNSSEC and a validation failure is invisible.** Decided on thin ground and marked as such on the ruling
- **HTTP/3, and any QUIC listener** — ruled out in [#62](https://github.com/winniel123/verge-asm/issues/62) while closing the ALPN list. `h3` cannot be selected in a TLS-over-TCP ClientHello, so this is **not an ALPN gap**: an HTTP/3-only service has no TCP `Service` for an `Endpoint` to hang off and is invisible one layer earlier, at `reachability`. The honest statement is that v1's aperture is TCP, which is also where [#29](https://github.com/winniel123/verge-asm/issues/29)'s UDP claim already sat
- **TLS 1.3 cipher-suite enumeration, and NULL / EXPORT / anonymous suites** — ruled out in [#62](https://github.com/winniel123/verge-asm/issues/62), and neither is a cost ruling. Go's `Config.CipherSuites` is documented as ignored for TLS 1.3, so those three suites are **not ours to declare**, and a per-candidate negative over candidates we did not choose would move estate-wide on a library upgrade — *TLS 1.0/1.1 negotiated* a third time, arriving through the scope record. Nothing is lost: all three are AEAD and none is a finding. NULL, EXPORT and anonymous suites are simply not implemented by Go at any setting, which makes **"does this listener accept a NULL cipher" a question v1 cannot put** — the sharpest missing capability in the offer list, and it becomes available only if the TLS library changes or is replaced
- **A facet-level change channel for `dns-record`** — refused in [Which facet `Transition`s besides the internet `Reach` leg are messages?](https://github.com/winniel123/verge-asm/issues/64). *Your MX record changed* is a real finding and a future session will reach for it, because `dns-record` is the one facet v1 records and never notifies on. It is refused as [ADR-0007](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0007-drift-is-a-timeline-of-spans.md)'s named burst shape verbatim — *a `dns-record` rule that fires per qtype per name* — and because no v1 rule reads the facet at all ([#48](https://github.com/winniel123/verge-asm/issues/48)'s two read the *composed* `resolution`). The cost is stated: an MX, TXT or NS change reaches nobody in v1. Deferrable with **no rework and no drift consequence**: the legal route is a `Signal` under [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md)'s cadence test, which [#35](https://github.com/winniel123/verge-asm/issues/35) established #16's list does not bar, and adding a rule *opens* a timeline so it costs no `Break`. What is out of scope is the **channel**, not the rule
- **Certificate-transparency mis-issuance detection, and any CT-fed facet** — ruled out for v1 in [Which subject does a certificate-transparency observation key on, and is CT a certificate source at all?](https://github.com/winniel123/verge-asm/issues/56). *A certificate exists for your name that nothing in your estate presents* is a real finding and it is the reason anyone wants CT in the `certificate` facet. It fails on **three** grounds, and [#48](https://github.com/winniel123/verge-asm/issues/48)'s expectation that fixing the keying would unlock it was backwards. **The keying ground is confirmed, not repaired**: after [ADR-0027](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0027-a-source-may-admit-without-observing.md) CT holds no timeline at all — no facet, no value, no `Span` — so a rule has nothing to evaluate. **#48's conflation ground stands**: CT is append-only, so a certificate for a long-dead name sits in the log forever, and *a certificate was mis-issued* against *a certificate outlived its name* are opposite facts under one predicate — the case [ADR-0015](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0015-the-value-space-is-the-commitment.md) expressly distinguishes from licensed commonness. **And a third, measured, that #48 did not have**: the rule is a set difference between logged and presented certificates, and **[measured] the join key does not exist on the instrument that ships** — `crt.sh` returns no fingerprint — while the one that carries `cert_sha256`, SSLMate Cert Spotter, was excluded on terms by [ADR-0003](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0003-third-party-source-consent-bar.md) for failing limb 2 (*"for personal or evaluation purposes"*). Genuinely deferrable rather than merely deferred, and the price is written down: it needs a **new facet** on `Name` recording issuance, which [ADR-0011](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0011-a-facet-is-six-parts.md)'s strictly-additive rule and ADR-0015 price at **`revealed` plus one message with no `Break`** — so v1.1 may take it up with no rework. One warning it inherits: a set-valued monotone facet fed by an instrument with a documented **999-row cap that truncates silently under an HTTP 200** is [ADR-0009](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0009-verge-core-is-a-union.md)'s `{161}` defect arriving through the *value* instead of the key. Note the first ground is measured on `crt.sh` as it behaves today — if a fingerprint field ever appears it evaporates, and the other two do not
- **A `sensitive-port-reached-from-internal` signal** — refused in [On a one-vantage-class install there is no Exposure — which bare Reach transitions wake someone?](https://github.com/winniel123/verge-asm/issues/58). The obvious way to give the one-legged internal install a sharp alert through machinery that already exists, adding no measurement — and it fails on evidence rather than cost. [#21](https://github.com/winniel123/verge-asm/issues/21)'s list is attested for what is *never legitimately internet-facing*; internally a Redis on 6379 is the **correct** configuration, which is the entire reason `verge-core` probes it, so the list ranks nothing on that leg. Reading it there is [#46](https://github.com/winniel123/verge-asm/issues/46)'s truncated-conditional shape — a claim used outside the context that gives its only operative term meaning. Unlike most entries here this is not deferrable-with-no-rework so much as **wrong**: it would become legal only if somebody attested a list of ports that are never legitimately reachable from an operator's own network, which is a different instrument with different evidence
- **An `http-acceptance` facet** — enumerating which HTTP versions a listener accepts, the symmetric object to `tls-acceptance`. Ruled out in [Is everything our client offers an aperture input, or only the TLS candidate set?](https://github.com/winniel123/verge-asm/issues/54) on pricing rather than principle: [ADR-0015](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0015-the-value-space-is-the-commitment.md) prices a wholly new facet at `revealed` plus one message with **no `Break`**, so there is no deadline and nothing to buy now. It is the honest home for *which HTTP versions this listener will speak*, which v1 deliberately does not record — the negotiated version is refused outright as *TLS 1.0/1.1 negotiated* one facet across, a fact about our own client rather than about the world
- **Distinguishing h2c with prior knowledge from non-HTTP bytes in cleartext** — ruled out in [Is everything our client offers an aperture input, or only the TLS candidate set?](https://github.com/winniel123/verge-asm/issues/54). Telling a gRPC listener on a plain port from bytes that are not HTTP needs a second probe sending an HTTP/2 connection preface at whatever is on the port, which is the class of risk against production that [ADR-0015](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0015-the-value-space-is-the-commitment.md) deferred the wire-protocol prober over and that [#4](https://github.com/winniel123/verge-asm/issues/4)'s profile has not budgeted. The TLS-side case is bought instead by a wider ALPN offer (`h2, http/1.1`), which is free in Go, so what remains is cleartext only. The cost is stated rather than hidden, and `NoHTTPResponse` is honest about it where `NotHTTP` was not
