## Destination

A written v1 spec for verge-asm — an AGPL-3.0, self-hosted, single-tenant web application that takes seed domains and IP ranges, discovers internet-exposed assets via passive sources then active probing, and makes **exposure drift a first-class, queryable object with its own lifecycle — tracked across ports, certificates, DNS records and HTTP identity, not subdomains alone** — complete enough to hand to implementation sessions.

That emphasis is the differentiation, and it is deliberately narrow: the prior-art survey established that discovery, probing, scan-to-scan diffing and the risk signals all exist in open source today. What does not exist is change modelled as a durable object across every asset facet. The spec must earn that claim or the effort has no reason to exist.

## Notes

- **Plan, don't do.** This map produces the spec, not the implementation. Every ticket resolves a decision.
- **Recommendations are pre-accepted — run every ticket AFK.** Standing instruction from the map's dev, 2026-08-13: *"I'm taking all your recommendations on the grilling tickets. Assume I'm going with your recommendations unless I come in and say otherwise. I want to make this as AFK-able as possible."* This **overrides the ticket-type HITL rule** for this effort — `grilling` and `prototype` tickets run without waiting on a live human, which is the override the skill routes through this section. What it does **not** license is skipping the interrogation: `/grilling` and `/domain-modeling` still run in full, the session just argues both sides itself and rules, rather than leaving the question hanging. Three riders bind. **The resolution comment is where review happens, so it must be reviewable** — it names the option that lost and why it lost, because a recommendation taken silently is one the dev cannot disagree with later. **Do not manufacture consensus**: where the evidence genuinely underdetermines the answer, say so in the comment and rule anyway, flagging it as a decision taken on thin ground rather than dressing it as settled. And **stop for a scope change, never for a preference** — a resolution that would redraw the Destination, or that costs money, sends mail to a third party, or is otherwise hard to walk back, is put to the dev; everything short of that is the session's call.
- **Licence: AGPL-3.0.** The network copyleft is deliberate. Dependencies and design choices must be compatible; flag anything that would force a licence change.
- **Defensive posture.** The operator owns the assets being scanned, so no scope-consent machinery is needed — but probing safety against the operator's own production is a live concern. **Qualified by [ADR-0002](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0002-ownership-gates-probing.md):** discovery follows records outward, so "the operator owns it" is not automatically true of what discovery reaches. Ownership is derived per address and *gates* probing, which is how the premise is kept true rather than assumed.
- **Single-tenant, self-hosted** via `docker compose`. No multi-tenancy, billing, or hosted infrastructure in scope.
- **The user** is a small-org security owner. The product answers: *what of ours is exposed to the internet, and what changed?*
- **The instance is a high-value target.** Its database is a complete, current map of the operator's attack surface. Security decisions are weighed against that, not against the app's size.
- **Differentiation is narrow, and must not be overstated.** "No OSS tool does exposure drift" is **false** — see the prior-art ticket. reNgine ships working subdomain drift with scheduling and alerting. The defensible claim is narrower: drift as a *first-class, queryable object with a lifecycle*, tracked across **ports, certificates, DNS records and HTTP identity** rather than subdomains only. Any session that finds itself writing "nothing else does this" should re-read that ticket. **The margin has since narrowed**: reNgine's unreleased `release/3.0.0` rewrite already models ports, IPs, DNS and full certificate data, and still diffs subdomains only — so the gap is now *temporal modelling alone*, not data coverage. If 3.0 ships drift across the facets it already stores, this map's differentiation is gone. Re-check `api/app/services/scan.py` and `worker/app/orchestrator/finalize.py` on that branch for any diff over a model other than `Subdomain`.
- **The operator-supplied zone file is the product's spine.** A defensive tool can ask for ground truth that an offensive recon script must guess at. Every guess-based technique is gap-filling for what the zone doesn't cover. This is a structural advantage over the offensive-framed tools in the prior-art survey, and it should be visible in the domain model, the onboarding flow, and how the project describes itself.
- **A source that errors must produce no observation, never an observation of absence.** Measured: crt.sh returns spurious 404s. In a drift product, "non-200 means empty" manufactures false "asset removed" alerts.
- **Use the glossary's words.** [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/main/CONTEXT.md) is opinionated about vocabulary and explicit about what it refuses: **`Asset`**, **`Host`**, **`Finding`**, **`ScanRun`**, and `Discovery`/`Probe` as nouns are all rejected, each for a stated reason. A session reaching for one of them is usually about to re-introduce the failure that rejected it.
- **The design system exists and is not optional.** [`design-system/`](https://github.com/winniel123/verge-asm/tree/main/design-system) — "engineered paper": warm paper `#f7f7f4`, ink `#16160f`, one working blue `#2d4fd4`, 0px radius, hairline rules, hard offset shadows, Helvetica for UI and IBM Plex Mono for every technical value. Any session producing a visual surface — production UI, prototype, mock, slide — invokes the `verge-asm-design` skill first. Rules in [`docs/agents/design-system.md`](https://github.com/winniel123/verge-asm/blob/main/docs/agents/design-system.md). **Its visual layer is canonical; its vocabulary and IA are not** — the kit predates [#7](https://github.com/winniel123/verge-asm/issues/7) and ships a `Findings` section, a fingerprinting claim, and a Dashboard-first layout with *no drift screen at all*. Where the kit and the glossary collide, the glossary wins and the visuals get re-skinned around it.
- **Skills:** `/grilling` + `/domain-modeling` for HITL tickets; `/research` for AFK research tickets; `/prototype` for UI tickets — and `verge-asm-design` alongside `/prototype`, always.

## Decisions so far

- [Prior art: what existing OSS ASM platforms already do, and where the gap is](https://github.com/winniel123/verge-asm/issues/2) — **no technically novel gap exists.** reNgine already computes added/removed subdomain drift on a cron with alerting; XingRin advertises verge-asm's exact pitch; the proposed risk signals are commodity httpx/Nuclei output. The defensible gap is narrower: drift as a first-class queryable object, across ports/certs/DNS/HTTP rather than subdomains only. `docs/research/prior-art-oss-asm.md`
- [Free passive discovery: what CT logs, DNS, and RDAP yield without API keys](https://github.com/winniel123/verge-asm/issues/3) — **Tier 0** (no third party): own resolver, RFC 4592 wildcard detection as a mandatory prerequisite, operator zone file or authorised AXFR, IANA→RIR RDAP (ARIN org-name→**202 CIDRs** in two keyless requests). **Tier 1:** CT logs direct, crt.sh throttled to 5 req/min, Common Crawl. CT firehose tailing out for v1; passive DNS effectively unavailable keylessly. **Its ToS filter is superseded by [#15](https://github.com/winniel123/verge-asm/issues/15)** — most exclusions were availability, not terms — and its RIPE recipe is corrected by [#20](https://github.com/winniel123/verge-asm/issues/20) (`type-filter=organisation`, never `inetnum`). The measurements stand; the tiering does not. `docs/research/passive-discovery-sources.md`
- [Safe active probing profile for scanning your own production](https://github.com/winniel123/verge-asm/issues/4) — TCP connect, non-root, zero added container capabilities. Tiered port sets — ~140-port hot set daily, top-1000 weekly, full range opt-in — because `nmap-services` frequency data is from **2008** and misranks modern exposure (Redis 1683rd). Rate limits **per target host**, not global. `GET /` not HEAD; redirects unfollowed because the redirect *is* the finding; credentials never submitted. Its §7.3 damping is overruled by [#35](https://github.com/winniel123/verge-asm/issues/35), its §2.5 UDP list superseded by [#29](https://github.com/winniel123/verge-asm/issues/29), and its 3 s/2-retry timeout is a versioned prober parameter per [#49](https://github.com/winniel123/verge-asm/issues/49). `docs/research/safe-active-probing.md`

neither is compressible by policy. **[#56](https://github.com/winniel123/verge-asm/issues/56) re-prices the first half upward**: `certificate` keys on **`Endpoint`**, not `Service`, so *every open `Service`* is the **floor** — the nameless endpoint's timeline — and the real count multiplies again by names per service, which on a shared-hosting or CDN-fronted address is the largest multiplier in the model; **[#61](https://github.com/winniel123/verge-asm/issues/61) answers the rate**: the handshake rides the `reachability` exchange, so a `certificate` timeline accrues a span opportunity **per reachability batch covering its port** — daily for `verge-core`, and never on a slower clock than the `Service` itself, while `tls-acceptance` accrues weekly on its own `Scan`; both are now sizeable. **[#62](https://github.com/winniel123/verge-asm/issues/62) adds a third multiplier and a floor under the second**: the `certificate` handshake is a *separate connection* from the HTTP exchange, so an endpoint costs a chain handshake plus an HTTP handshake plus the `tls-acceptance` enumeration — and [#4](https://github.com/winniel123/verge-asm/issues/4) §6's 5 handshakes/s per host is the cap all three share. **[#49](https://github.com/winniel123/verge-asm/issues/49) adds a break cause we do not control** — prober leaves move on a **dependency** cadence, so whoever sizes this is sizing against `go.mod` and upstream release schedules; the relief is that those breaks are narrower than any previously priced here. **[#54](https://github.com/winniel123/verge-asm/issues/54) narrows it again**: a Go upgrade can no longer widen the TLS offer, so it fires one break rather than two, and the *aperture* half of the dependency cadence is now ours to schedule

Current membership is a **lookup** (the open `Span`), so the hard part is not *what is here* but **which populations render alongside the living, and which can be listed without a comparison at all** — which is what stays fog. - How the tiered port sets are curated and revised over time — **the governance half only**, since [#21](https://github.com/winniel123/verge-asm/issues/21) discharged the evidence half and [ADR-0009](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0009-verge-core-is-a-union.md) removed the derived set's maintainer entirely (nobody revises a definition). So this is about **two inputs with incompatible evidence standards**: who revises the frequency set and the sensitive list, on what trigger, and how often. The trigger is not *a service became popular* — that is frequency, the wrong instrument — but **a primary source changing its position or a protocol changing its shipped defaults**. Urgency is higher than it looks: [#21](https://github.com/winniel123/verge-asm/issues/21) found attesting sources move much faster than release-coupling assumes (BOD 22-01 revoked, CISA's CPG renumbered, CIS abandoning named ports, Prometheus *softening* after gaining native TLS), so a policy assuming static sources will be wrong within a year. Cost is fully priced and composes cleanly: revising the frequency set manufactures **no drift at all**, while a sensitive-list revision costs a version bump *and* an aperture widening yielding `revealed`, landing on different objects. What stays fog is only **who pulls the trigger, and on what watch** — and [#60](https://github.com/winniel123/verge-asm/issues/60) adds a **third** curated input with the same question and a weaker evidence base than either: `certificate-expiring`'s **30-day horizon**, now a project-authored declared parameter inside that rule's own leaf. Unlike the other two it is a single integer, so revising it manufactures one `Break` on one rule for one cadence and nothing else; unlike `k` and the availability window it makes a claim about the **world** rather than about our own measurement, and #60 recorded its ACME-renewal rationale as **stated but unverified against a source**, which is exactly the shape [#57](https://github.com/winniel123/verge-asm/issues/57) caught. Whoever discharges this patch should verify it under [#21](https://github.com/winniel123/verge-asm/issues/21)'s standard or move the number. **[#33](https://github.com/winniel123/verge-asm/issues/33) discharges the third input and gives this patch its first concrete task.** `certificate-expiring`'s 30-day horizon is routed to [#67](https://github.com/winniel123/verge-asm/issues/67) as a retrieval, so it stops being this patch's to verify — and a **fourth** curated input arrives with it, `certificate-weak-key-or-signature`'s key-size floor and algorithm set, which has never been written down at all ([#68](https://github.com/winniel123/verge-asm/issues/68)). The trigger this patch was looking for is now **named and enumerated**: [ADR-0032](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0032-an-evidence-standard-attaches-to-a-table-not-to-a-rule.md) §8 found that §10.4's *a shipped default attests only where it restricts* creates **silent de-attestation** — a row admitted on a restricting default loses its footing the moment that default turns permissive, and **nobody publishes a retraction**; a config default flips in a major release. The exposed rows are exactly those resting on a restricting default alone — **5432/tcp, 5984/tcp, 9042/tcp** — which are exactly [#21](https://github.com/winniel123/verge-asm/issues/21)'s published weak tier, so **the weak tier is the watch list** and the disclosure made for honesty turns out to have an operational consumer. `161/udp` is **not** on it: its weakness is a corroborator standing where an owner should, which no release can change — one kind is watched, the other is chased ([#66](https://github.com/winniel123/verge-asm/issues/66)). The check nobody has run, and this patch's first task: **whether any of the three defaults has already moved.** Marked derived rather than measured. **[#66](https://github.com/winniel123/verge-asm/issues/66) falsifies the stated trigger as complete.** The patch names the trigger as *a primary source changing its position or a protocol changing its shipped defaults* — and the first actual removal from the sensitive list was caused by **neither**. Nothing in the world moved: a retrieval that had never been performed was performed, and a row that had been on the list since [#21](https://github.com/winniel123/verge-asm/issues/21) turned out to rest on a corroborator. So the trigger set needs a third member — *a row's footing was never checked against the standard it is now held to* — which is a **backlog** obligation with an end rather than a watch, and whoever discharges this patch should say whether that backlog is finished. [#60](https://github.com/winniel123/verge-asm/issues/60)'s 30-day horizon is the same shape, and #33 has since routed it to [#67](https://github.com/winniel123/verge-asm/issues/67) as a retrieval — the first item on that backlog. **[#67](https://github.com/winniel123/verge-asm/issues/67) discharges that first backlog item and removes the third input from this patch entirely.** `certificate-expiring`'s horizon is no longer a curated number: it is a **fraction** read from the certificate at evaluation time, so nobody revises it when a lifetime changes and it joins neither the watch list nor the chase. **It also adds a trigger the patch does not have**, and it is worse than both existing ones because it needs *nobody to do anything*: **silent staleness**, where a project-authored constant that is the product of a fraction and a moving world quantity goes wrong on arithmetic while every document it cites still says what it said. `N = 30` was **stale before it was written** — Certbot had already removed its fixed 30-day threshold in 4.0.0 when #60 recorded the rationale. Whether other constants are in that class is [#71](https://github.com/winniel123/verge-asm/issues/71), and it is a **sweep with an end**, not a watch. **[#68](https://github.com/winniel123/verge-asm/issues/68) writes the fourth input and makes its watch nearly free.** `certificate-weak-key-or-signature`'s table is five rows whose measured cadence is about **one edit per row per decade** — nine changes in twenty-two years, next scheduled ~2030 — so its correct posture is *re-read SP 800-131A when a revision goes final, and otherwise do nothing*, against the port list's continuous drift. It also adds a **third kind of weak row** to this patch's watched/chased pair: a **scope** weakness, where the owner has spoken but scopes its own normative verbs (NIST's *shall* is *a requirement for Federal Government use*). It cannot flip silently, so it is not watched; it cannot be chased by finding the right party, because the right party has already spoken — it resolves only if a **second** owner speaks unscoped, which is [#73](https://github.com/winniel123/verge-asm/issues/73) and is a search of a corpus rather than a request to a party. Two things #68 refused belong to this patch's trigger set as **permanent** exclusions rather than watch items: a **key-compromise blocklist** (Debian, ROCA, shared moduli) grows continuously and is #31's signature database, and **encoding NIST's dated transitions as date comparisons** would move a rule's output at midnight with no version bump — *a scheduled cryptographic transition is a scheduled edit, never a live date in a predicate*

A case in that gap is to be ticketed, never decided by whoever meets it

## Out of scope

- **Full vulnerability scanning** (nuclei templates, CVE detection) — v1 reports only risk signals that fall out of probing for free
- **Operator-authored signal rules** — ruled out for v1 in [Risk signals: which ones does v1 emit from cert and protocol facts alone?](https://github.com/winniel123/verge-asm/issues/16). A user-written rule is an un-versioned, un-reviewed derivation inside the comparison path that per-rule versioning and the alerting gate exist to make trustworthy — and the first thing anyone would write is the signature matching [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md) deliberately excluded, re-entering through a door we opened ourselves. Plausible for v1.1 once `Annotation` and the versioning story have run in production. The tension is worth keeping visible: the release-coupling test is defensible for **what we ship**, and becomes paternalistic if it is still refusing the operator's own corpus in v2
- **Technology fingerprinting** (Wappalyzer-style signature detection) — ruled out in [Build, vendor, or shell out for discovery and probing?](https://github.com/winniel123/verge-asm/issues/5) on drift-integrity grounds, not cost: a fingerprint verdict is a function of the signature database, so diffing it reports a change in the observer as a change in the world, across the whole estate at once. The general rule it generalises to — *only observed values enter drift* — binds beyond this one feature
- **A JSON API and API tokens for programmatic access** — ruled out for v1 in [Stack and runtime for web, worker, and persistence](https://github.com/winniel123/verge-asm/issues/6). With a server-rendered htmx UI no API falls out for free, so shipping one is a deliberate act — and an API token is a bearer credential that **bypasses the TOTP** decided in [#11](https://github.com/winniel123/verge-asm/issues/11), guarding a database that is the operator's complete attack surface. The integration need is **push, not pull**: nobody polls an ASM tool, they want to be told when the internet `Reach` leg goes `not-reached` → `reached` ([ADR-0029](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0029-an-alert-fires-on-a-leg.md); this entry originally said `firewalled` → `exposed`, a cell pair, before [#45](https://github.com/winniel123/verge-asm/issues/45) made it a block and [#58](https://github.com/winniel123/verge-asm/issues/58) made it a leg), which the in-scope notification-channels question already carries. A session-authed CSV/JSON export covers getting the data out with no new credential class
- **Cloud provider connectors** (AWS/Azure/GCP CAASM) — deferred past v1
- **Hosted multi-tenant SaaS** — self-hosted only
- **Offensive / bug-bounty workflows** against assets the operator does not own
- **SSO / OIDC / reverse-proxy forward-auth** — decided against for v1 in [Auth and access model for a self-hosted deployment](https://github.com/winniel123/verge-asm/issues/11); header-trust auth is a bypass class of bug when the proxy is misconfigured, and OIDC is real implementation work the v1 destination doesn't require
- **A `partially-lame-delegation` signal** — ruled out for v1 in [Does dangling-delegation join the v1 signal set, on evidence that is a failure?](https://github.com/winniel123/verge-asm/issues/35). A delegation where some but not all nameservers are lame is a real resilience defect and a real precursor to the total case, but the name still resolves, so `resolution` has not moved and nothing about the estate's exposure changed. The per-nameserver detail is still **recorded** on `dns-record`, so this is deferred rather than discarded and v1.1 can add the rule with no rework
- **A rule comparing the zone file's records against what the authority serves** — deferred in [Does zone-declared-name-does-not-resolve join the signal set, and what else does per-source keying expose?](https://github.com/winniel123/verge-asm/issues/48). *Your file says this MX and your zone serves that one* is a real config-drift finding and it is refused for v1 on [ADR-0004](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0004-signals-are-release-coupled-rules.md)'s own test arriving one level down: a zone export expresses things the wire does not — provider `ALIAS`/`ANAME` pseudo-records, apex CNAME flattening, `$GENERATE`, `$INCLUDE`, provider-side DNSSEC signing, SOA serials, apex NS sets the provider rewrites — so the decoder needs a stripper per convention forever, and a signal's effective version composes its decoder's. [ADR-0013](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0013-custody-is-control-and-extends-by-declaration.md) already refused to rest a safety property on this same ground, Route 53's API distinguishing `ALIAS` from `A` where **Cloudflare's is unmeasured**, failing *silently*. Deferred rather than discarded: it becomes legal the moment somebody measures what the major providers' exports actually emit, and that same measurement is what would price the noise floor of `resolved-name-absent-from-zone`. The v1 rules stay on the readable side of one line — **a rule may read which names a zone contains, never what records it holds for them.**
- **The wire-protocol prober and the `listener-negotiation` facet** — ruled out for v1 in [Does the observation-driven listener rule ship in v1, and at what granularity?](https://github.com/winniel123/verge-asm/issues/41). A new facet, a versioned canonicaliser with a golden corpus, plus prober `Derivation` leaves of its own, per-protocol encoders and parsers, a ~14-row dispatch table and an expanded safety surface against production — buying **six ports** and **zero** net new firings across all 38 rows of the sensitive list. It is genuinely deferrable rather than merely deferred: the facet is wholly new, so every timeline it opens is an *opening*, and [ADR-0011](https://github.com/winniel123/verge-asm/blob/main/docs/adr/0011-a-facet-is-six-parts.md) prices the whole addition at `revealed` plus one message with no `Break`. The cost is stated rather than hidden — v1 loses the AMQP `ANONYMOUS` measurement (the clearest case in the survey of reaching where the curated list cannot), IMAP's `LOGINDISABLED` conditional MUST (the best-founded row in the note), and RDP's *is CredSSP required* on a port [#21](https://github.com/winniel123/verge-asm/issues/21) had to exclude. §5's per-protocol costing in [`docs/research/insecure-listener-rules.md`](https://github.com/winniel123/verge-asm/blob/main/docs/research/insecure-listener-rules.md) is preserved so a later effort can take protocols one at a time; the first thing it must close is the question §7.2 skipped — it argues a wrong dispatch guess fails safe for the *data* and never asks whether it is safe for the *listener*. **[#49](https://github.com/winniel123/verge-asm/issues/49) corrects this entry's pricing of the corpus and makes the deferral cheaper than it reads.** "A golden corpus of a new kind (captured wire transcripts)" is wrong on the medium: corpus rows are **authored peer scripts with a claim in prose**, run hermetically in-process, and captured transcripts are refused outright because a capture carries no claim for a human to review.
