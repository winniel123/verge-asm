# v0.1.1

The first published release of verge-asm.

`v0.1.0` was tagged first and published nothing. Its pipeline run stopped on a defect in
the workflow's own build-stamp assertion, so no images were tagged and no Release was
created. A tag is spent once pushed, so the repair ships under this number. There is no
`v0.1.0` release and there never will be.

> ⚠️ **Alpha software.** Expect breaking changes, incomplete features, and rough edges.
> Interfaces, the database schema, and behaviour may change without migration paths
> between releases. Do not depend on it for production security monitoring yet. Review
> it yourself before you run it against anything you care about.
>
> The project is on `0.y.z`. A minor bump may carry a breaking change while the major
> is `0`.

## What this is

Self-hosted attack surface management for your own estate. Its subject is not inventory
but **change**: what of yours is exposed to the internet, and what moved since last time.

You declare seed domains and IP ranges. verge-asm discovers the internet-exposed assets
that grow from them, probes what custody allows, and records exposure drift as a
queryable timeline across ports, certificates, DNS records and HTTP identity. It runs as
a single-tenant web application under `docker compose`. AGPL-3.0.

Read [`docs/guides/running.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/docs/guides/running.md)
to install it. Read [`docs/spec/v1-spec.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/docs/spec/v1-spec.md)
and [`CONTEXT.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/CONTEXT.md) for
why it behaves as it does.

## What this release publishes

Two multi-arch images, `linux/amd64` and `linux/arm64`:

- `ghcr.io/winniel123/verge-asm/web:v0.1.1`
- `ghcr.io/winniel123/verge-asm/worker:v0.1.1`

Both carry keyless Sigstore signatures and SLSA v1.0 Build Level 2 provenance, under one
Fulcio identity and no verge-asm public key. Each platform image carries its own SPDX
SBOM attestation.

The Release assets carry the digest-pinned `docker-compose.yml`, the environment sample,
the external-database overlay, eight SBOM documents, the Trivy scan reports, and a
`SHA256SUMS` list with its own Sigstore bundle.

**Verify before you run it.** The commands are in
[`docs/guides/verifying-releases.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/docs/guides/verifying-releases.md).
An air-gapped route is in
[`docs/guides/verifying-releases-airgapped.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/docs/guides/verifying-releases-airgapped.md).

## Two things to know before you install

**A source build is never told a release shipped.** Every published release carries a
bare `vX.Y.Z` tag and stamps a bare `X.Y.Z` version. A version string carrying a suffix
did not come from this pipeline. That is a convention backed by the tag ruleset, not a
cryptographic guarantee.

**`docker compose up` is not a verification path.** With the tag absent locally it
attempts the pull, warns, then builds from source and exits 0. A registry you cannot
reach produces a source build rather than an error.

## Known gaps

- The release feed's update check is **off by default** and fully declinable. With it
  disabled the instance makes no network call ever, not even on boot.
- `v0.1.1` cannot be withdrawn. `/releases/latest` returns 404 when no non-prerelease
  release remains, which would break every instance's update check. The first published
  release is superseded by the next one, never withdrawn. See
  [`CONTRIBUTING.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/CONTRIBUTING.md).
- Rolling back is documented in
  [`docs/guides/running.md`](https://github.com/winniel123/verge-asm/blob/v0.1.1/docs/guides/running.md).
  An image downgrade is not a schema downgrade: `web` applies migrations at startup and
  nothing ever runs a `goose` down block.
