# ADR-0107: The `dns` `Scan` resolves the names CT admitted, and their `Citation` stays the admission that introduced them

- **Status:** Accepted
- **Date:** 2026-08-16
- **Ticket:** [#255 Resolve CT-admitted names: feed `admitted_name` into the `dns` Scan (wave-1)](https://github.com/winniel123/verge-asm/issues/255)
- **Map:** [#1 Map: verge-asm v1 spec](https://github.com/winniel123/verge-asm/issues/1)

## Context

[#250](https://github.com/winniel123/verge-asm/issues/250) / [ADR-0106](./0106-the-ct-poll-is-a-scan-that-schedules-and-a-ct-admission-is-a-name-citing-its-batch.md) built the crt.sh runner and materialised [ADR-0027](./0027-a-source-may-admit-without-observing.md)'s *admits without observing* as a durable **`admitted_name`** row — the `Name`, the covering `Seed`, and the admitting `Batch` (the `Citation` hop). ADR-0106 then drew this ticket by name and refused to build it inside a fetch-and-parse change: *"Feeding `admitted_name` into the `dns` `Scan`'s resolution set (wave-1), so an admitted `Name` becomes a measured member, is the ticketed successor — stated in the ADR, not built here, since it is an estate-widening change with its own golden-corpus obligations."*

This is that successor, and its first finding is that it is **not a new feature — it discharges a claim three ADRs already rest on.** [ADR-0027](./0027-a-source-may-admit-without-observing.md) said *"a CT-admitted name acquires a `resolution` timeline from our own `enumerable` resolver within one cadence, and leaves by Name Error like any other. CT needs no timeline for the model to work."* [ADR-0006](./0006-subjects-leave-by-measurement.md) rested its *the residue is not immortal by this decision* argument on *"every known name is re-resolved every cycle."* [ADR-0096 §1](./0096-a-citation-never-ages-it-is-contradicted-and-only-an-enumerable-sources-silence-can-do-it.md) built its entire *no aging needed* ruling on it: *"#142 has since supplied the clock … our own resolver's `resolution` timeline is now covered by the `dns` `Scan`, daily, `k` = 2. So a CT-admitted name that stops existing is withdrawn within two days, by measurement."*

**All three are false in code today.** `fanOutDNS` resolves `ListNameSeedDomains` and only that — the name-scope `Seed` domains — so a discovered `Name` in an `admitted_name` row is never handed to the resolver. The `admitted_name` table is *written and never read*: there is no `SELECT` against it anywhere. So the load-bearing sentence *acquires a `resolution` timeline within one cadence* is prose the code does not honour, and the `admitted_name` row is inert provenance. This ticket makes the sentence true by unioning the `admitted_name` population into the `dns` `Scan`'s resolution set — the single, honest change the corpus has been written against since ADR-0027.

What made it `ready-for-human` is that resolving discovered names touches four surfaces the runner ticket deliberately did not: the **control-probe population** (an aperture input, ADR-0066), **`wildcard-discrimination`** (`Shadowed`/`Lame` committed jointly, ADR-0084), the **probing gate** and **`Custody`** (a consent boundary, ADR-0013/0019), and the **`Citation` display** hop (ADR-0027 says the CT `Batch`; `GetNameCitation` returns the earliest resolution). Each is resolved below. The finding across all four is the same: the widening flows through machinery the model **already** records by content and gates by declaration, so wave-1 adds no aperture plumbing and no new consent surface.

## Decision

| Concern | Decision |
| --- | --- |
| The resolution set | `fanOutDNS` resolves the **union of the name-scope `Seed` domains and the current `admitted_name` names**, deduplicated. This is the first read against `admitted_name` |
| What "current admitted name" is | The **distinct set of admitted names**, unconditional of the `crtsh` source's *current* enablement. Resolution is the `dns` `Scan`'s act, not the source's; membership is measured and durable; ADR-0003 consent was spent at admission, when the source was enabled |
| Seed scope vs. resolution set | Admitted names enter the job's **`Names` (resolution set) only, never its `seeds`** (the control-probe bound). The `seeds`/`Names` split ADR-0106 already built into `scan.go` carries this exactly — its comment already reads *"in v1 the resolution scope is the seed domains themselves,"* anticipating this divergence |
| Control-probe population | **Widens automatically and is recorded by content**, unchanged. It is the parents of the resolved names intersected with the `Seed` scopes (ADR-0066); unioning admitted names into `Names` while leaving `seeds` the `Seed` set makes their parents fall inside the gate and be probed, and a wildcard at or above the apex stays out of reach by the existing rule. No new field, no new plumbing |
| `wildcard-discrimination` | **Runs over the wider `Names` unchanged.** `Shadowed`/`Lame` are decided per name against the (now wider) control population and committed jointly with `resolution` (ADR-0084). A CT-admitted name under a `Shadowed` answer or a `Lame` delegation is ADR-0006/§0096's already-ruled residue, reached at a second door — not reopened |
| Membership | **Measured, unchanged.** An admitted `Name` becomes a current member when its latest `resolution` outcome is not `NameError`/`Shadowed` (`ListCurrentNameSubjects`) and leaves by Name Error — discharging ADR-0027/0096 §1 in code. A `Citation` is necessary and not sufficient (ADR-0096 §5) still holds: the `admitted_name` row never put it in the estate; the measurement does |
| Entry class of a first resolution | **`revealed` (Coverage), by the existing rule** — a subject first seen under a widened aperture is `revealed`, not `appeared` (ADR-0031). The drift engine decides this from the aperture recorded **by content** on the `Batch`; because the resolution scope and control-probe population are already recorded there, no message logic changes |
| The probing gate / `Custody` | **Unchanged and not widened.** CT discovery populates the resolution set `NameCitedAddresses` reads; the `Custody` gate still admits only the operator's **declared** address scopes and Custody-extension zones (off by default). A CT-discovered name under a declared extension zone is probed on **identical footing** to a seed-resolved name under it — the extension is defined over *names under the zone*, never over discovery path. An operator who declared no extension sees no new probing |
| `Citation` reconciliation | **The admission wins.** `GetNameCitation` returns the **current `admitted_name` `Batch`** when one exists — the CT admission is what *introduced* the name (ADR-0027: the hop is the `Batch`). The earliest-`resolution`-batch remains the citation for names never admitted (a `Seed` apex, a CNAME target). Provenance answers *why is this here*; the measurement answers *is it here now* |
| Golden corpus (ADR-0041) | **Not weakened, because the leaf corpora are population-independent.** `resolutionwalk` and `wildcarddiscrim` render scripted per-subject rows against an in-process peer; a wider *live* population moves no leaf digest and no `Corpus` lock. The membership-deciding outcomes (`Resolved`/`NameError`/`Shadowed`/`Lame`) are already covered per subject and run over an admitted name unchanged. The wave-1 seams — the union/dedup and the citation precedence — are covered by unit tests |
| The `dns` `Scan`'s aperture inputs | **Seven, unchanged** (ADR-0084/0106). A wider *population* under an input is not a new *input*; the diff of the recorded control-probe population is exactly how the widening surfaces as `revealed` |

## Rationale

### It is a correctness fix, and the union is the whole of it

The estate is observation-derived: a `Name` is in it through a `resolution` observation, and nothing else puts it there (ADR-0006, ADR-0096 §5). CT produces no observation, so an `admitted_name` row is a promise the resolver has to keep — *this name entered by CT; measure it and it becomes a real member or leaves by Name Error.* Until the resolver is handed the name, the promise is unkept and every downstream sentence that quotes it (*within one cadence*, *re-resolved every cycle*) is aspirational. The union keeps the promise, and because the estate reads membership off the `resolution` timeline rather than off any discovery list, that is **all** it takes: once the name carries a `resolution` observation, `ListCurrentNameSubjects`, `NameCitedAddresses`, the membership vector and `returned` detection all light up on their own, over the observation corpus, with no seed join to widen.

### The widening is recorded, not silent — because the aperture is recorded by content

ADR-0106's worry was that resolving discovered names *"moves the control-probe population (an aperture input), changes what `wildcard-discrimination` reads, and — once those names resolve to addresses — reaches the probing gate and `Custody`."* Every one of those is true, and every one is already honest, because the model made the control-probe population **the seventh aperture input, recorded on the `Batch` by content** (ADR-0066): the parents of the resolved names, intersected with the `Seed` scopes. Widen the resolved names and the parent set widens with them, is written down as it happened, and the drift engine's ordinary aperture diff detects the widening and narrates the entering subjects as `revealed` (Coverage), not `appeared` (Drift). This is the ADR-0025 discipline paying out: because *what we looked at* travels by content, looking at more is self-describing. There is no hidden field to add and no message to special-case.

The one piece of care is that the widened population must **not** widen the `Seed` scopes that *bound* the control probes — a control label is a subject nowhere, gated at the `Seed`, and admitting the discovered names as `Seed` boundaries would let a wildcard be tested above the operator's apex. ADR-0106 already fixed this: the job's `seeds` field is distinct from its `Names`, and its own comment anticipated the divergence. So the seam is *union into `Names`, leave `seeds` the `Seed` set* — one line, on machinery built for it.

### The probing gate stays where consent put it, and that is why this is safe AFK

The sharpest question is consent: once a CT-discovered name resolves to an address, is that address probed? The answer is *only on the ground the operator already declared*, and the reason is that the probing gate is **address-scoped and `Custody`-gated**, never name-scoped and never discovery-aware. `Custody` is derived from three inputs (`hotEstate`): the operator's declared **address scopes**, the operator's declared **Custody-extension zones** (off by default), and the **current resolutions**. CT discovery grows only the third. The *gate* over it is unchanged: an address is admitted only if it sits in a declared scope, or the name resolving to it sits inside a declared extension zone.

So a CT-discovered `vpn.example.com` → `1.2.3.4` is probed exactly when a *seed-resolved* name under `example.com` → `1.2.3.4` would be: when the operator has declared an address scope over `1.2.3.4`, or a Custody extension over `example.com`. The extension's own words are *names under this zone resolve to addresses I control* — and `vpn.example.com` **is** a name under `example.com`, whatever found it. CT discovery does not enlarge what the operator consented to; it finds more of the names the consent already spoke about. An operator with no extension and no covering scope sees no new connect. This is the check against the stop-rule: wave-1 opens no new probing surface, redraws no Destination, spends nothing, mails no third party, and is a one-line revert — so it is ruled here, not escalated.

### The `Citation` is the admission, because provenance and membership are different questions

`GetNameCitation` today returns the earliest live `resolution` observation's `Batch`. For a CT-admitted-then-resolved name that is the *introducing measurement*, and it is the wrong answer to the question a `Citation` asks. A `Citation` is *why is this here* (`CONTEXT.md` `Citation`): the single hop to the thing that introduced the subject. What introduced `vpn.example.com` is CT — we resolved it **because** CT admitted it; a citation naming the resolution would answer *why is this here* with *because we resolved it*, which begs its own question. ADR-0027 already fixed the answer — *"the hop is that source's `Batch` … stored as an `admitted_name` row"* — and ADR-0096 §5 made it durable past withdrawal: *"a `Name` withdrawn by a measured Name Error and a live CT citation coexist."* A citation that flipped to the resolution on first measure and vanished on Name Error would contradict both.

So the reconciliation is forced, not chosen: **`GetNameCitation` prefers the current `admitted_name` `Batch` when one exists**, and the chain still terminates at a `Seed`, because the `admitted_name` row carries `seed_id` — ADR-0027's *"the covering `Seed` the chain terminates at."* A name with no admission (a `Seed` apex, a CNAME target discovered in a resolution) is unchanged: its citation is the earliest resolution, terminating at its covering `Seed` by suffix. Membership stays measured and stays on the `resolution` timeline; the two questions are answered by the two records, each by the one that honestly bears on it.

### The residue is not reopened, and the corpus is not weakened

ADR-0006 and ADR-0096 §2 already ruled the immortal residue — names under a `Shadowed` answer or a `Lame` delegation, which the resolver can never Name-Error — and ruled it *stays, visibly unconfirmed, leaving by one of three honest routes.* Wave-1 reaches that residue through a second door (a CT-admitted name that is `Shadowed`/`Lame`), and changes nothing about it: it is the same residue under the same rule, and this ADR does not re-litigate it. Nor does it weaken ADR-0041's golden coverage: the membership-deciding leaves render scripted subjects against an in-process peer, so the size of the *live* estate is not an input to a single golden byte. The corpus proves the leaves decide `Resolved`/`NameError`/`Shadowed`/`Lame` correctly per subject, and those same leaves run over an admitted name with no new code path to leave uncovered.

## Consequences

- **`fanOutDNS` reads `admitted_name` for the first time**, unioning its distinct names into the resolution set and leaving the control-probe bound the `Seed` set. Every downstream corpus read (`ListCurrentNameSubjects`, `NameCitedAddresses`, the membership vector, `returned`) widens on its own, over observations, with no further edit.
- **ADR-0027/0006/0096 §1's *acquires a `resolution` timeline within one cadence* is now true in code.** The three ADRs that quoted the future can be read in the present tense.
- **A CT-admitted name that resolves enters as `revealed` (Coverage), not `appeared` (Drift)** — the aperture widened, the world did not — and leaves by measured Name Error like any other name. Its `Custody` and probing are decided by the operator's declared scopes/extension exactly as for a seed-resolved name.
- **`GetNameCitation` prefers the `admitted_name` `Batch`.** A CT-admitted name shows its CT admission as its citation before, during, and after membership; a never-admitted name is unchanged.
- **[`CONTEXT.md`](../../CONTEXT.md) is amended** at `Source` (the `admitted_name` row now feeds the `dns` resolution set; wave-1 is done, not owed), `Citation` (the display precedence: the admission over the introducing resolution), and the `dns`-`Scan` note (its resolution scope is the name-scope Seeds **and** the CT-admitted names beneath them).
- **The consent surface is unchanged and stated as such**, so a later reader does not mistake the wider probed estate for a widening of the gate. The gate is the operator's declaration; CT grows the population under it, never the gate.
- **No new `Scan`, no new facet, no new observation, no new aperture input.** Wave-1 is a population change under existing inputs, recorded by the existing by-content machinery.

## Alternatives rejected

| Alternative | Why not |
| --- | --- |
| **Gate the resolution set on the `crtsh` source being *currently* enabled** — resolve an admitted name only while consent is live | Conflates two acts. Resolving is the `dns` `Scan`'s DNS query by our own resolver, not a crt.sh fetch; ADR-0003 consent is spent at **admission**, and a `Name` already in the estate leaves only by measurement (ADR-0006), never by a toggle. Gating resolution on the source would silently drop measured members when the operator stops *discovering*, which is a withdrawal by omission the model forbids |
| **Admit CT names into the estate directly, so they appear without waiting for a resolution** | The ADR-0027 decoder rule and ADR-0096 §5: admission is not membership, a `Citation` is necessary and not sufficient. Manufacturing membership from an admission fabricates a `resolution` nobody measured and re-imports the *append-only never leaves* defect ADR-0096 spent a whole ADR closing |
| **Union admitted names into the job's `seeds` as well as its `Names`**, treating a discovered name as a scope boundary | Breaks the probing gate: `seeds` bound the control-probe population at the operator's apex, so a discovered name as a `Seed` would let a wildcard be tested above the apex and pull a parent the operator never declared into the probed set. The `seeds`/`Names` split exists precisely to keep the resolution set wider than the scope bound |
| **Leave `GetNameCitation` on the earliest resolution and surface the admission elsewhere** | Answers *why is this here* with *because we resolved it*, which is the question restated, and contradicts ADR-0027 (the hop is the `Batch`) and ADR-0096 §5 (the citation outlives the membership). The admission is the introduction; the citation names the introduction |
| **Widen the resolved population but add a new aperture input for "discovered-name coverage"** | There is no new input. The control-probe population is *already* the recorded aperture, by content, and a wider population under it is detected by the ordinary diff. A new input would double-record the same widening and invite the next session to think a discovery scan needs one — the hidden-field inversion, mirror-imaged |
| **Build wave-1 as a distinct discovery→measurement pipeline** rather than a union into `dns` | The hidden-`Scan` failure ADR-0084/0106 refused. A CT-admitted name is resolved on the `dns` `Scan` by definition (ADR-0096 §1); a second pipeline would resolve the same names under a name that does not claim the `dns` cadence, and disabling `dns` would leave it running |
